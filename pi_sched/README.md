# pi_sched — 命令の並べ替えが Cortex-A72(Raspberry Pi 4)で効くかを測る一式

`IMPLEMENTATION_NOTES.md` には「命令の並べ替え(重み付きの表スケジューリング: 読み 4・乗算 3・除算 8)は入っているが、Cortex-A72 向けの調整はしていない。実機の速さは未測定」とある。この一式は、**並べ替えが実機で速くしているか**を調べる。A72 は out-of-order の CPU なので、並べ替えなしでも同じ速さかもしれない(その場合、並べ替えを A72 向けに調整する意味は小さい)。

## 変種(プログラムごとに 3 つ)
- `_o`: `--no-opt`(最適化を全部切る)
- `_n`: 最適化あり、命令の並べ替えだけ切る(`SIGN_SCHED=0`)
- `_s`: 全部あり(既定)

**`_n` と `_s` の差 = 並べ替えの効果**、`_o` と `_n` の差 = 並べ替え以外の最適化(レジスタ割り付けなど)の効果。

## プログラム(`src/`)
`mulchain`(独立な乗算 4 本)・`divloop`(割り算と余り)・`memsum`(表からの連続読み)・`horner`(独立な多項式 4 本)。どれも約 1 秒(Pi 4)の長さの繰り返し。答えは処理系(インタープリタ)が出し、`expected.json` に置いてある。毎回の実行で照合する。

## Pi 4 で
1. このフォルダごと Pi へ(`scp -r pi_sched pi@…:`)。`bin/` の ELF は x86 のこちらで作ってある(静的・AArch64)。
2. 他の処理を止め、できれば冷えた状態で: `python3 run_on_pi.py`(既定 5 回の中央値。回数は引数で)。
3. できた `report.txt` を貼る。見るのは `並べ替えの効果 n/s` — 1 より大きければ並べ替えが速くした。1 前後なら A72 では差が出ない。

作り直し(`bin/` と `expected.json`): `python3 make.py`(約 1 分)。
