# 第11巻『Raspberry Pi で Sign を動かす』

2026-11-08 · @たににゃん

## はじめに

この巻は、Sign の処理系を Raspberry Pi 4B と 3A+ で動かすための手順書です。結論から言うと、**コンパイルは要りません**。処理系は Python だけで書かれていて、標準ライブラリしか使わないので、Python 3 が入った Pi なら、ファイルを置くだけで動く作りです。

**確かめた範囲** この巻の実行は、すべて Pi ではないパソコン(x86 の Linux、Python 3.13 と 3.11)で行いました。確かめたのは次の 3 つです。

- 全部のテスト(35 本)が Python 3.13 で通ること。
- GPIO・I2C・SPI・画面・システムコールなどの装置のテスト 8 本が Python 3.11 でも通ること。
- 全ファイルの文法が Python 3.8 の読み方でも通ること(これは書き方の検査で、実行ではありません)。

**確かめていない範囲** この巻の内容(Python の処理系)は、本物の Raspberry Pi では確かめていません。処理系とは別の道の AArch64 向けの出力は、Raspberry Pi 4 Model B と Pi 3 A+ の実機で試験を通していますが、この巻の対象ではありません。Pi の OS、パッケージ名、配線、GPIO・I2C・SPI の本物の部品、動く速さは、すべて未確認です。Pi の側の事柄(OS の版と Python の版、`apt` の名前、`raspi-config` の項目)は私の知識で書いたもので、お使いの OS で違うことがあります。そういう所には【Pi 側・未確認】と付けました。印の無い記述は、この環境で確かめたことです。

**仕様と実装** GPIO・I2C・SPI などの装置は、Sign の仕様書には無い、この処理系だけの追加です(各レシピに【拡張】と付けます)。ほかの処理系では動きません。

## 第1章 用意する

### レシピ1 Python の版を確かめる

**やりたいこと** Pi に入っている Python で、この処理系が動くかを先に知りたい。

**操作** Pi の端末で次を打ちます。

```bash
python3 --version
```

**実行結果** Raspberry Pi OS の版で入っている Python が違います。私の知識では、Bullseye が 3.9、Bookworm が 3.11、Trixie が 3.13 です【Pi 側・未確認】。この処理系を実際に動かして確かめたのは 3.13 と 3.11 です。この 2 つなら試験が通りました。より古い 3.9 では、書き方の検査(3.8 の読み方)は通りましたが、実行は確かめていません。

**ひとこと** 3.9 の Pi で動かなかったときは、出たエラーを教えてください。その版向けに直せます。

### レシピ2 ファイルを Pi にコピーする

**やりたいこと** 処理系とサンプルを Pi のホームに置く。

**操作** いちばん簡単なのは、パソコンから `scp` で送る方法です。ユーザー名とホスト名(`pi`、`raspberrypi.local`)は例で、ご自分の Pi の名前に置き換えます。パソコン側で、処理系のあるフォルダを開いて実行します。

```bash
ssh pi@raspberrypi.local mkdir -p sign
scp sign.py sign_*.py std.sn *.sn pi@raspberrypi.local:sign/
```

**実行結果** Pi の `~/sign` に、`sign.py`、`sign_interp.py` をはじめとする `sign_*.py`、`std.sn`、サンプルの `*.sn` が並びます【Pi 側・未確認】。

**ひとこと** `sign_*.py` は全部送ってください。GPIO や I2C の装置は、`--gpio` や `--i2c` を付けたときに初めてそのファイル(`sign_gpio.py`、`sign_bus.py`)を読み込むので、無いとそのときに初めてエラーになります。`std.sn` は、サンプルの多くが先頭で ``std.sn`@~` と読み込むので、同じフォルダに置きます。

## 第3章 GPIO・I2C・SPI をつなぐ

この章の装置は、すべて【拡張】です。ピンやセンサーは「番地を読み書きする」だけで扱います(GPIO の基点は `0x9500000`、I2C は `0x9600000`、SPI は `0x9700000`)。ここでは、練習用の「偽物」のバックエンド(`fake`)を使って、パソコンで確かめたことと、本物の Pi でやることを分けて書きます。**Pi のピンにつないだ LED やセンサーでは、一度も動かしていません。**

### レシピ7 LED を点滅させる(GPIO)

**やりたいこと** 17 番のピンにつないだ LED を、500 ミリ秒ごとに点けたり消したりする。

**操作** つなぎ方は、`led_gpio.sn` の先頭にあります。GPIO17(基板の 11 番ピン)── 330Ω の抵抗 ── LED の足の長い方(+)、LED の短い方(−)── GND(例: 9 番ピン)です。まず、本物のピンを使わない練習用で動かします。

```bash
python3 sign_console.py led_gpio.sn --display=null --gpio=fake
```

**実行結果** 標準エラーに、`[gpio] 17 = 0`、`[gpio] 17 = 1`、`[gpio] 17 = 0` と、交互に出続けます(3 秒で止めて確かめました)。つなぎ直したところで、`--gpio=fake` を `--gpio` に変えると、本物のピンを動かすつもりの呼び出しになります。

```bash
python3 sign_console.py led_gpio.sn --display=null --gpio
```

**ひとこと** `--gpio` を省くと、バックエンドは自動で選ばれます。gpiozero、RPi.GPIO、どちらも無ければ `fake` の順です。**どちらも無いと**** ****`fake`**** になり****、****標準エラーに****「注意: gpiozero も RPi.GPIO も見つからないので、練習用の fake を使います(本物のピンは動きません)…」と 1 度出ます**(この環境で確かめました)。この注意が出たときは、本物のピンは動いていません。LED が光らないときは、まずこの注意と、`[gpio] 17 = 1` のような行(`fake` が出す)が出ていないかを見てください。本物のピンが権限などで使えなかったときは、理由が標準エラーに 1 度だけ出て、プログラムは落ちずに続きます。止めるのは Ctrl+C で、止めると LED は消えます。ピンの番号は基板の番号ではなく、GPIO 番号(BCM)です。

**確かめていないこと** 本物の LED の点滅、gpiozero と RPi.GPIO のどちらでも動くこと、権限の要否。

### レシピ8 LED をゆっくり明るく・暗くする(PWM)

**やりたいこと** 同じ配線で、明るさを変える。

**操作**

```bash
python3 sign_console.py led_pwm.sn --display=null --gpio=fake
```

**実行結果** `[gpio] 17 pwm 0% 1000Hz`、`[gpio] 17 pwm 2% 1000Hz`、`[gpio] 17 pwm 4% 1000Hz` と、デューティが 2% ずつ増えていきました。デューティは、基点 + `0x200` + 4×ピンの番地に 0〜1000(1000 が 100%)で書きます。周波数は基点 + `0x300` + 4×ピンです。

**ひとこと** RPi.GPIO を使うときの PWM はソフトウェアで行うため、OS の負荷で明るさや周波数がずれます。

**確かめていないこと** 本物の LED の明るさの変わり方と、ちらつき。

### レシピ9 I2C の部品を探す

**やりたいこと** I2C でつないだ部品のアドレスを知りたい(Linux の `i2cdetect` と同じ)。

**操作** まず練習用の偽物で、アドレス `0x48` と `0x50` に部品があることにします。

```bash
python3 sign.py i2c_scan.sn --i2c=fake:0x48,0x50
```

**実行結果** `0x48`、`0x50` と出て、最後に最後の式の値 `0` が出ました。本物の Pi では、I2C を有効にして(`sudo raspi-config` の Interface Options、【Pi 側・未確認】)、バス 1(GPIO2 が SDA、GPIO3 が SCL)につないでから、次を実行します。

```bash
python3 sign.py i2c_scan.sn --i2c=smbus2
```

**ひとこと** `--i2c` の後ろは、バックエンドを選ぶ所です。省くと、smbus2 があればそれ、無ければ `fake` になります。**smbus2 が入っていない Pi で ****`--i2c`**** だけを付けると、****標準エラーに「注意: smbus2 が見つからないので、練習用の fake を使います…」と 1 度出て、部品は 1 つ****も見つから****ないまま****正常に終わります。** この環境(smbus2 なし)で `--i2c` だけで `i2c_scan.sn` を動かすと、この注意のあとで `0` だけが出ました。部品が 1 つも見つからないときは、まずこの注意が出ていないかを見てください。`--i2c=smbus2` と名前で指定しておけば、入っていないときは理由を出して終了コード 1 で終わります(この環境で確かめました)。

**確かめていないこと** 本物のバスでのスキャン、センサーの値の読み取り(AHT25 の見本 `aht25.sn` も偽物でしか確かめていません)。

### レシピ10 SPI を自己診断する

**やりたいこと** 部品をつなぐ前に、SPI の配線をチェックする。

**操作** MOSI(GPIO10)と MISO(GPIO9)を 1 本の線でつなぎ、送った 4 バイトがそのまま戻るかを見ます。まず練習です。

```bash
python3 sign.py spi_loopback.sn --spi=fake
```

**実行結果** `1 2 3 4` と出ました。本物の Pi では、SPI を有効にして(`raspi-config`、【Pi 側・未確認】)から、`--spi=spidev` を付けて実行します。`1 2 3 4` なら成功、`0 0 0 0` なら線がつながっていません(見本の先頭の説明より)。

**ひとこと** **この自己診断は、****`--spi`**** だけでは****注意が要ります****。** spidev が入っていないと、`--spi` だけでも練習用の `fake` になり、標準エラーに「注意: spidev が見つからないので…」と出ます。それでも、線をつないでいなくても `1 2 3 4` と出ます(この環境には spidev も SPI の機器もなく、このとおりになりました)。`1 2 3 4` だけで成功と思わず、この注意が出ていないかも見てください。本物を診断するときは、`--spi=spidev` と名前で指定してください。入っていないときは、理由を出して終了コード 1 で終わります(この環境で確かめました)。

**確かめていないこと** 本物の配線での結果。

### レシピ12 音を鳴らす

**やりたいこと** WAV と、ど・み・その音を鳴らす。

**操作** まず、音の無い練習用で動かします。

```bash
python3 sign.py sound_demo.sn --sound=fake
```

**実行結果** 標準エラーに、`[sound] ``play chime.wav` のあと、`[sound] tone ``26``2Hz 300ms`、`330Hz`、`392Hz`、`523Hz` の 4 つの音(ド・ミ・ソ・ド)が順に出て、最後に `0` が出ました。本物の Pi では、`--sound=fake` を `--sound` に変えます。このとき、`chime.wav` と `sound_demo.sn` は同じフォルダに置きます。

### レシピ14 ネットワークを使う

**やりたいこと** Pi を TCP のサーバーにする。

**操作**

```bash
python3 sign.py echo_server.sn --net=local
```

**実行結果** `待ち受け開始` と `9000` が出ます。同じパソコンの中から 127.0.0.1 の 9000 番へつないで `hello pi` を送ると、そのまま返ってきました。続いて接続を閉じると、プログラムは `0` を出して終わりました。

**ひとこと** `--net=local` は、その Pi の中だけです。ほかのパソコンからつなぎたいときは `--net` を使いますが、待ち受けが `0.0.0.0` になるので、同じネットワークの誰でもつなげることに注意してください(見本の先頭の説明より)。

**確かめていないこと** Pi での実行。他のパソコンからの接続。

### 装置とバックエンド

名前を省くと、部品が無いときに `fake` になるのは、GPIO・I2C・SPI・音の 4 つです。このとき、標準エラーに「注意: …」と 1 度出ます。本物で確かめるときは、名前を付けて指定するほうが確実です(無いと理由を出して終わります)。

| 装置 | 基点 | 付ける指定 | 本物のバックエンド | 練習用 |
|---|---|---|---|---|
| 画面 | `0x9100000` | `--display=` | `window`(tkinter) | `png`、`ascii`、`null` |
| GPIO | `0x9500000` | `--gpio` | `gpiozero`、`rpigpio` | `fake` |
| I2C | `0x9600000` | `--i2c` | `smbus2` | `fake`、`aht25:温度,湿度` |
| SPI | `0x9700000` | `--spi` | `spidev` | `fake` |
| 音 | — | `--sound` | 再生コマンド、pygame、simpleaudio | `fake` |

### 4B と 3A+ の違い

3A+ はメモリが 512MB、4B は 1〜8GB と、私は理解しています【Pi 側・未確認】。この処理系は、この環境でスイカゲームを画面なしで動かしたとき、最大で約 20MB しか使いませんでした(かかった時間は約 0.5 秒ですが、パソコンでの数字で、Pi での速さを示すものではありません)。メモリの点では、どちらでも余裕がある見込みです。速さは、Pi で実際に測るしかありません。

### この巻を書くときに直した処理系の不具合

部品が入っていないときの振る舞いを試して、次の 2 つを見つけ、直しました。どちらも、Pi を使うときに真っ先に当たりやすい情報です。

- `--gpio=gpiozero`、`--i2c=smbus2`、`--spi=spidev` のように、入っていない部品や知らない名前を指定すると、Python のトレースバックで落ちていました。いまは、`エラー: 装置を用意できません…` と理由を出して、終了コード 1 で終わります。
- `--display=window` で tkinter が無い、または画面(DISPLAY)が無いと、トレースバックで落ちていました。いまは、理由を出して窓が閉じられたことにして終わります。

どちらも試験を足し、関係する試験を通しています。さらに 3 つ目として、名前を省いて `fake` になるときに、標準エラーへ 1 度「注意: …」と知らせる形にも変えました(GPIO・I2C・SPI・音)。部品が無いことに気づかないまま、偽物で「成功」と見えることを防ぐためです。
