この巻は、Sign のプログラムが「エラー」「警告」「知らせ」を出したときに、何を言われているのかを読み取り、直すための本です。メッセージの意味は、種類ごとに実際に出した例で確かめました。

## はじめに

読み方は2つあります。出た画面のメッセージの名前(`undefined-name` や `body-bare-row-between` など)から第6章の早見表を引くか、第1章から順に読みます。

他の巻と同じ印を使います。**【仕様】** は配布された仕様書が決めていること、**【実装】** はこの処理系の動きで、仕様が決めていない所や、メッセージの文面そのものです。メッセージの文面は【実装】です。名前(`undefined-name` など)と、止まるか続くかの区別は、仕様に書かれています。

**どのモードで見るか。** 他の巻の例は既定のモードで動かしました。この巻は、知らせと警告を見るのが目的なので、例によって `--strict` を付けます。【実装】既定のモードでは、警告と知らせの多くは画面に出ません。出る例外は取り込むファイルが無いときの知らせ(第4章)で、構文のエラーは両方のモードで出ます(場所の示し方は同じで、文面が違う例もあります)。

確かめた版は「alpha1 実装 2026-11-06 00:50 JST」です。

シリーズ全体は、[全巻の案内](README.md)で見られます。

## 第1章 出てくるものの種類

画面に出るものは、頭の言葉で見分けます。違いは「これでプログラムが止まるか」です。

| 頭の言葉 | 意味 | 実行は | 例 |
|---|---|---|---|
| `エラー:` | 読めない・断られた | 止まる | `body-bare-row-between`、`name-shadow`、`interpret-work-limit` |
| `警告:` | 値が消えるなど、意図と違うかもしれない | 続く | `leftover-lambda` |
| `知らせ:` | 言い添え | 続く | `undefined-name`、`zero-division`、`bare-function-return`、`import-not-found` |

【仕様】診断の名前と重さ(information、warning、断り)は仕様が決めています。`undefined-name` と `pointfree-not-folded` は information、`leftover-lambda` は warning で、どちらも「断らない(止めない)」診断です。

【実装】画面の頭の言葉(`エラー:`・`警告:`・`知らせ:`)と、文面はこの処理系のものです。ここで「知らせ」と呼ぶのは information のことです。

### 場所の見方

`エラー:` は、頭に「ファイル名:行:桁:」が付き、その下に、該当の行と印(`^`)が出ます。

```
エラー: e3.sn:1:8: 式が必要です
     1 | x : (1 + 
       |        ^
```

`警告:` と `知らせ:` は、行の最後に `[3 行目]` のように行が付きます(桁はありません)。読む段で出る知らせでは、行が付かないものもあります(第4章の `undefined-name`)。

### 静的検査 `--check` の言葉

`sign.py --check ファイル` は、実行せずに読んで知らせます。別の言葉を使います。

| 括り | 画面の種類 | 意味 |
|---|---|---|
| 断り | `error` | 仕様の断り |
| 注意 | `note` | 断りではない、気をつけてほしいもの(未定義の名前など) |
| 参考 | `hint` | この検査器が足したもの。仕様の断りではない(重複した定義など) |

【実装】終わりのコードは、断りがなければ 0、あれば 1、読めない・構文の誤りなら 2 です(断りがある場合の 1 は、この巻では確かめていません)。`--werror` を付けると、注意も断りとして数えます。`--no-hint` で参考を出さず、`--unused` で使われていない定義も出します。

## 第2章 止まらない失敗と、止まる失敗

Sign は、多くの失敗をエラーにせず、定義の無い値 `_`(画面では `__`)にして続けます。これがいちばんの落とし穴です。画面に何も警告が出ないまま、答えが静かに変わります。

### 打ち間違いの名前は、答えから消える

```
zz9
```

既定のモードでは `__` とだけ出ます。次は、名前を打ち間違えた計算です。

```
zz9 + 1
```

既定のモードでは `1` と出ます。定義の無い名前は足し算から落ちて、答えが「間違いに気づかない 1」になります。`--strict` で走らせると、こう出ます。

```
知らせ: undefined-name: `zz9`: 定義が無い名前は `_` で、使う所で読みます(…)
```

直し方は、名前を直すか、定義を足すかです。第4章で詳しく読みます。

【仕様】定義の無い名前は値 A で、情報 `undefined-name` を出します。断りません(R21)。【実装】情報は `--strict` でだけ画面に出ます。

### 0 で割る

```
5 / 0
```

既定のモードでは `__` です。`--strict` では、答えの前に次の知らせが付きます。

```
知らせ: zero-division: 0 で割ったので _ です(V5・V11) [1 行目]
```

同じ知らせは、何回起きても1回だけ出ます(`5 / 0` と `7 % 0` を並べても、知らせは1つでした)。

### 止まらない輪

終わりに届かない輪を書くと、輪の形とモードで止まり方が変わります。同じ状態へ戻る輪は、既定のモードでも止まります。

```
lp : n ?
	n = 0 : 0
	lp n
lp 5
```

この例は、どちらのモードでもすぐ止まります(既定のモードで 0.05 秒、終了コード 1)。メッセージもどちらでも同じで、「4 行目の」と行が付きます(実測し直しました)。次のように出ます。

上は既定のモード、次は `--strict` の出力です。

```
エラー: interpret-not-yet: 4 行目の末尾の輪が前に通った状態(同じ関数・同じ実引数)へ戻りました。止まらない輪(アイドル)です。この実装は輪を回さずに止めます(V10・V12。`_` は返しません)
```

次のように、実引数を終わりの条件へ近づける向きに変えると、どちらのモードでも `0` で終わります。

```
lp : n ?
	n = 0 : 0
	lp (n - 1)
lp 5
```

実引数が同じ状態に戻らず、ただ終わりを見ない輪(`lp (n + 1)` のように増え続ける形)もあります。`--strict` では、計算の量が上限に届いたところで次のように止まります。既定のモードには計算の量の上限がないので、この形は止まりません(40 秒待っても終わらず、打ち切りました)。

```
エラー: interpret-work-limit: 3 行目の計算の量が上限(5,000,000 回)に届きました。止まらない輪かもしれません(末尾の輪が同じ状態へ戻らない形。V10)
```

【実装】上限の回数(5,000,000)はこの処理系の選んだ値です。【仕様】は、計算の量の上限と、同じ状態へ戻る輪(アイドル)を見つけて止めること(V10・V12)を定めていますが、回数の値は実装の都合とされています。

### 終わりのコード

【実装】`エラー:` で止まった実行の終わりのコードは 1、最後まで動いた実行は 0 でした。警告や知らせが出ても、最後まで動けば 0 です。

## 第3章 読む段で止まる書き方の誤り

プログラムを読む段階で止まる誤りです。この種類は、`エラー:` で止まり、プログラムは1行も動きません。ですから、最初に直すものです。ここに並べた例は、すべて既定のモードで実際に出し、直した形も同じように動かして確かめました。

| 画面の言葉 | 原因 | 出した例 | 直した形 |
|---|---|---|---|
| `式が必要です` | 演算子の後ろに式が無い | `x : 3 +` | `x : 3 + 4` |
| `閉じ括弧がありません` | `(` や `[` を閉じていない | `(a` や `x : [1 2` | `(a)` |
| `字句エラー` | 閉じていない文字列の引用符 | `x : `abc` | `x : `abc`` |
| `解釈できないトークン: '?'` | `?` の左にあるのが、名前でない仮引数 | `f : 5 ? 1` | `f : x ? 1` |
| `body-bare-row-between` | 枝のある本体の途中に、裸の行がある | 下の例 | 下の例 |
| `block-after-value` | 値で終わる行の下に、字下げのブロックがある | `x : 1` の下に `	``2` | メッセージの指示に従う |
| `infix-missing-operand` | 括りの中の演算子の前後に空白が無い、中置の相手が無い | `(+ 1 _)` | `[+ 1]` |

場所は、`ファイル:行:桁:` で最初の誤りを示します。桁は目安です(第5章の G7 の例では、行の頭を指していました)。この種類のエラーでは、`block-after-value` だけは場所が付きませんでした。メッセージの中に例があるので、字下げのブロックを置いた行を自分で探します。

### 枝のある本体の途中の裸の行(`body-bare-row-between`)

```
f : a ?
	a > 0 : 1
	a * 2
	a * 3
f 1
```

既定のモードで次のように出ます。場所は、最初の裸の行(3 行目)を指します。

```
エラー: s3.sn:3:2: body-bare-row-between: 枝の行のある本体で、最後の行でない裸の行があります(枝の前・枝の間・既定の行が2つ以上)。裸の行は最後の1行だけです(R130)
     3 | 	a * 2
       | 	^
```

【仕様】枝の行(`条件 : 値`)が1つでもある本体では、裸の行は最後の1行だけです(R130)。【実装】読む段で、最初の裸の行の位置(行と桁)を示して止めます。

直し方は、裸の行を最後の1行にするか、枝にするかです。次は、裸の行を最後の1行だけにした形です。`f 0` は `0` になりました。

```
f : a ?
	a > 0 : 1
	a * 2
```

### 括りの中の中置演算子(`infix-missing-operand`)

```
(+ 1 _)
```

既定のモードでは、「前置できない演算子 '+'(中置は前後に空白が必要。点なしなら `[+ 1]`。R119)」と出ます。`--strict` では同じ名前で、別の文面(「1行の括りの中の点なしの形の項の後ろに書いた `_` だけが続く並び…」)になります。どちらも、点なし(前置の演算子を関数として使う形)を書くなら、`[+ 1]` のように `[ ]` で括ります。確かめた結果は `[+ 1] 2` が `3` でした。

【仕様】この名前と、読む段で止めることは R119 で決まっています。【実装】文面はモードで違います。

### エラーではなく、静かに通る誤り

読む段で止めてくれない誤りもあります。次のように、関数に実引数を多く渡しても、エラーにはなりません。

```
f : x ? x + 1
f 2 3
```

既定のモードでは `[3, 3]` と出ます(余った実引数は答えの横に並びます)。「答えがなぜリストになったか」を後から読むときの手がかりにしてください。

## 第4章 知らせと警告の読み方

この章の主役は、プログラムを止めない診断です。【実装】既定のモードでは、`import-not-found` を除いて画面に出ません。出して見るには `--strict` で走らせます。以下の「出した例」は、実際に `--strict` で走らせて出た結果で、「直した形」のうち、leftover-lambda と bare-function-return の分は、警告と知らせが無くなることを確かめました。ほかの行の直した形は方針で、走らせてはいません。

| 名前 | 重さ | 何を言っているか | 出した例 | 直した形 |
|---|---|---|---|---|
| `undefined-name` | 知らせ | 定義の無い名前を使っている。値は `_` | `zz9` | 名前を直す、または定義を足す |
| `leftover-lambda` | 警告 | 関数が実引数を受けないまま残って、`_` になって消える | `f : x ? x + 1` の後に `f` だけの行、`5 inc` | `f 5`、`inc 5` |
| `bare-function-return` | 知らせ | 本体の返す所に裸の関数が残り、`_` を返す | 下の例 | `h : y ? sq y` |
| `zero-division` | 知らせ | 0 で割ったので `_` | `5 / 0` | 割る前に 0 でないことを確かめる |
| `import-not-found` | 知らせ | 取り込むファイルが見つからない | ``nofile.sn`@~` | ファイル名と置き場所を直す |

【仕様】`undefined-name` は information、`leftover-lambda` は warning で、どちらも断りません(R21・R48)。`bare-function-return` の“本体の返す所の裸の関数は `_`”は R125 です。

### `undefined-name`

```
f : a ?
	a > 0 : 1
	zz
f 0
```

`--strict` で走らせると、こう出ます。行は付きません(読む段で出すからです)。

```
知らせ: undefined-name: `zz`: 定義が無い名前は `_` で、使う所で読みます(…)
```

既定のモードでは `__` とだけです。【実装】`--strict` は、実行で通らない枝や、呼ばれない関数の中の名前にもこの知らせを出します(2026-11-05 00:10 の版から)。括りの仮引数を持つ関数の本体は、呼ばれるまで読まないので、この知らせも出ません(R25)。取り込み(`ファイル`@~)のあるファイルでは、読む段のこの知らせは出しません。同じ名前は1回だけ出します。

【実装】「定義がある」の判定は、ファイル全体の定義・欄・仮引数の名前の和で見ます。たとえば、別の関数に同じ名前の仮引数があると、定義の無い名前を見逃すことがあります(出しすぎないための選択です)。

### `leftover-lambda`

```
f : x ? x + 1
f
```

`--strict` で走らせると、次の警告が出ます。最後に「[2 行目]」が付きます。

```
警告: leftover-lambda: 値の後ろの関数が実引数を受けないまま残り、_ になって消えます(`5 inc` は 5)… [2 行目]
```

既定のモードでは `<fn/1>`(引数を 1 つ受ける関数)と出ます。この種類の警告は、「関数を呼ぶつもりで実引数を書き忘れた」ときによく出ます。`g : a b ? a + b` に `g 1` と 1 つだけ渡しても、同じ警告が出ました(受ける引数が足りないまま残るからです)。

`5 inc` を「5 に inc を当てる」と書いた場合も、同じ警告になります。

```
inc : x ? x + 1
5 inc
```

【仕様】実引数を関数の後ろに置くのが正しい書き方です(逆適用は廃止されました、R47)。【実装】既定のモードは、旧 alpha の互換として、この書き方をまだ通します(上の例は `6` と出ました)。ですから、既定で動くから正しい、とは言えません。`--strict` は警告を出して、答えを `_` にします。直した `inc 5` は、両方のモードで `6` でした。

### `bare-function-return`

```
sq : z ? z * z
h : y ?
	sq : z ? z * z
	sq
h 3
```

`--strict` で走らせると、次の知らせが出ます(最後に「[4 行目]」)。この例では、本体の中でもう一度関数 `sq` を定義していますが、本体の「`:` の行」は局所の定義ではなく枝です(R128)。

```
知らせ: bare-function-return: 本体の返す所に裸の関数が残り、_ を返します(R125)。関数を返すなら `$` を付けて持ち上げます(`$[+ m]`)、入れ子の `?` なら仮引数を並べます(`x y ? x + y`) [4 行目]
```

直し方は、関数を返すのではなく、当てた結果を返すことです。`h : y ? sq y` と書くと、`h 3` は両方のモードで `9` になりました。

### `import-not-found`

```
`nofile.sn`@~
1
```

この知らせだけは、既定のモードでも画面に出ます。

```
知らせ: import-not-found: 取り込むファイル `nofile.sn` が見つかりません。この取り込みは何も定義せず、そこから来るはずの名前は未定義(`_`)になります
```

【実装】プログラムは止まらず続き、この例では最後に `1` と出ました。ファイルを指す名前を直すか、読める場所へ置きます。よくある原因は、`std.sn` などを読み込むプログラムを、`std.sn` の無いフォルダで走らせたことです。この種類の誤りは、「取り込んだはずの名前がすべて `_` になっている」という形で現れます。

## 第5章 `--strict` の断りと、`--check` で先に見る方法

`--strict` は仕様の読みで、既定のモードは旧 alpha の互換です。既定では通るのに、`--strict` では `エラー:` で断られる書き方があります。その断りの名前は、`G7`・`G20`・`G21` のような種類番号と、`name-``duplicate` のような英語の名前の2種類があります。

### 仮引数が同じ名前の関数を隠す(`name-shadow`)

```
`std.sn`@~
sq : z ? z * z
f : sq ? sq + 1
println_int (f 3)
```

既定のモードでは `4` のあとに、最後の行の値の `0` が出ます。`--strict` では `4` が出て、続けて次の知らせが出ます。断られずに走ります。

```
知らせ: name-shadow: 仮引数 `sq` はファイルの定義 `sq`を隠します。この関数の中の `sq` は仮引数です(内側が勝つ。§4 R133)。 [3 行目]
```

【仕様】仮引数は、同じ名前の関数を隠します(内側が勝つ)。関数の中の `sq` は仮引数なので、`sq + 1` は `3 + 1` で `4` です。関数 `sq` を呼ぶつもりだったなら、仮引数の名前を変えます。`f : s ? ``(sq s)`` + 1` にすると、両方のモードで `10` になり、知らせも出ませんでした。【実装】以前の版の `--strict` は、この形を `エラー:` で断っていました。仕様が断りでなく知らせに決めたので、実装を合わせました。

### 同じ名前の2回目の定義(`name-duplicate`)

```
a : 1
a : 2
a
```

既定のモードでは `2` と出て、後の定義が前を隠します。`--strict` では、2つ目を断ります。

```
エラー: q5.sn:2:1: name-duplicate: 名前 a がファイルのいちばん外で 2 回定義されています(2つ目を断ります。P2)
     2 | a : 2
       | ^
```

直し方は、名前を分けることです。【実装】これは、`--check` では「参考」(`duplicate-definition`)としてしか出ませんでした。断りに数えられるのは、実際に `--strict` で走らせたときだけです。

同じ名前の重なりは、仮引数でも起きます。次のように、同じ関数の仮引数に `a` を2回書いた場合です(`dp.sn`)。

```
f : a a ? a
f 1 2
```

【実装】既定のモードでは `2` と出て、動きます。`--strict` では、次のように2つ目を断られました(終了コード 1)。

```
エラー: dp.sn:1:5: name-duplicate: 仮引数 a が同じ関数で2回書かれています(2つ目を断ります。P2。§4 R133)
     1 | f : a a ? a
       |     ^
```

これは、`--check --strict` でも実行せずに断られます。`dp.sn:1:5: error [strict-name-duplicate] <parse>: name-duplicate: 仮引数 a が同じ関数で2回書かれています…` と、`--strict` の実行と同じ行・桁を指し、「断り 1 件」で終了コード 1 でした(`--strict` を付けない `--check` では「断り 0 件・整合しています」です)。【実装】以前の版の `--check --strict` はこれを拾いませんでしたが、今は拾います。名前を分ければ(`f : a b ? a + b`)直ります。仮引数の名前が、ファイルの定義や外側の仮引数と重なるだけなら、断りではなく知らせになります(前の節の `name-shadow`)。

### `G7`　穴(`_`)を置けない所に置いた

```
q : 5
q , !_
```

既定のモードでは `[5, <Id>]` と出ます。`--strict` では、次のように、**修正案の行が付いて**断られます。

```
エラー: p1.sn:2:1: G7: !_ は中置演算子の被演算子に置けません(穴の位置の外)
  → 修正案: 穴は関数の実引数の位置にだけ置く。`!_ + 1` → `[+ 1]` か `x ? x + 1`
     2 | q , !_
       | ^
```

【実装】`→ 修正案:` の行は、すべての断りに付くわけではありません。この巻で上に出した `name-``duplicate` には付きませんでした。このメッセージの「修正案」は、例の形を直すヒントです。今のプログラムにそのまま当てはまるとは限りません。

この例では、桁が 1 で、誤りの `!_`(5 桁目)ではなく行の頭を指していました。行は合っているので、行の中のどこかは自分で探します。

### `--check` で先に見る

```
python3 sign.py --check file.sn
python3 sign.py --check file.sn --strict
```

実行せずに読んで、断り・注意・参考の件数を出します。先の `name-shadow` の例では、`--strict` を付けないと「断り 0 件・整合しています」で、付けると次のようになりました。断りでなく、注意に数えられます。

```
g3.sn:3:1: note [name-shadow] f: name-shadow: 仮引数 `sq` はファイルの定義 `sq` を隠します。この関数の中の `sq` は仮引数です(内側が勝つ。§4 R133)

g3.sn: 断り 0 件 / 注意 1 件 / 参考 0 件
```

【実装】`--check` は実行しないので、実行して初めて分かる断りは出しません。上の `G7` の例を `--check --strict` にかけても、こうでした。

```
p1.sn: 断り 0 件 / 注意 0 件 / 参考 0 件  → 整合しています
```

「整合しています」は、「この検査で見つからなかった」という意味です。`--strict` で実行しても断られない、という保証にはなりません。仕上げには、`--strict` で実際に走らせます。

## 第6章 困ったときの手順と、メッセージ早見表

### 手順

1. 画面の頭の言葉を見る。`エラー:` なら、その行を直す(第3・第5章)。
2. 答えが変だときは、まず `--strict` で走らせて、警告と知らせを出す(第2・第4章)。打ち間違いの名前や、実引数の書き忘れが見つかります。
3. 終わらないときは、`--strict` で走らせる。輪の形によっては、すぐ止めて理由を言います(第2章)。
4. 実行せずに先に見るときは `--check`(と `--check --strict`)。ただし「整合しています」を保証とは読まない(第5章)。
5. 既定と `--strict` で結果が違うときは、どちらが仕様の読みかは `--strict` です。既定は旧 alpha との互換です。[第8巻](08_spec-vs-impl.md)で、どちらがどうなのかを詳しく見ます。

## 確かめた範囲と、確かめていないこと

確かめたこと。

- この巻の例はすべて、「alpha1 実装 2026-11-06 00:50 JST」の版で、既定のモードと `--strict` の両方を実際に走らせ、出た画面を写しました。「直した形」も、実際に走らせて答えと知らせを確かめました。
- 終わりのコードは、実行では `エラー:` で止まると 1、最後まで動くと 0 でした。`--check` では、読めないファイルが 2、注意や参考だけでは 0 でした。`--werror` を付けると、注意のあるファイルも 1 になりました。「断りがあると 1」という結果は、この巻では確かめていません。

確かめていないこと。

- この巻に並べなかった診断、たとえば `G20`・`G21` や、`resource-depth` の知らせ。表に無い名前の読み方は、この巻では扱いません。

- Windows のコマンドプロンプトや PowerShell での起動。コマンドは Linux の bash で実行しました。
- `interpret-work-limit` の上限回数は実装の選んだ値です(仕様は回数を固定していません)。この値に依存しないでください。
