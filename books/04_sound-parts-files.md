## はじめに

この巻は、Sign で音を鳴らし、LED の明るさを変え、I2C・SPI の部品と話し、ファイルを読み書きするレシピ集です。『動くレシピ集』の第4章(LED とセンサー)の続きですが、単独でも読めます。文法の説明は『Sign入門』に任せ、ここでは動くコードと結果を並べます。

各レシピは「やりたいこと、全コード、実行結果、ひとこと」の順です。コードは実際に動かして結果を取っています。実行は既定のモードで行い、確かめた版は「alpha1 実装 2026-11-06 00:50 JST」です。

コマンドは、bash で打つ形で書いています。確かめたのは Linux の上だけで、Windows や macOS では試していません。

結果の出どころは、入れた印で区別します。

- **【仕様】** 配布された仕様書に書かれている動作です。この巻では、メモリの番地を `#` で書き `@` で読む動作がこれにあたります。
- **【実装】** `sign_interp.py` がそう動くだけで、仕様書に見つからない動作です。別の処理系では同じになるとは限りません。
- **【拡張】** 仕様に無い、この実装に添えた道具です。

この巻に出てくる装置は、すべて【拡張】です。音(基点 `0x9800000`)、GPIO の明るさ(基点 `0x9500000`)、I2C(基点 `0x9600000`)、SPI(基点 `0x9700000`)、ファイル(基点 `0x9400000`)、入力(基点 `0x9300000`)は、どれも「窓口」の形です。座標や命令の番号を決まった番地へ `#` で書き、命令の番地へ書くと実行され、結果を `@` で読みます。仕様にある `#` と `@` で窓口を読み書きするので、仕組みは仕様の上に載っています。ただし、ほかの処理系で同じ番地の装置が使えるとは限りません。

**確かめた範囲** 確かめたパソコンでは、音を聞くこともできず、Raspberry Pi の部品も、I2C・SPI の部品も使えません。そのため、次の練習用の装置で確かめました。音は、鳴らす内容を画面に書くだけの `--sound=fake`、I2C と SPI は、本物のバスを使わない `--i2c=fake:…` と `--spi=fake`、LED は `--gpio=fake` です。実際に音が鳴ること、LED が光ること、本物の部品が応答することは確かめていません。

印の無い記述は、ゲームやツールのルール、動かして見た結果の説明です。仕様書との一致を示すのは【仕様】の印だけです。Sign の資料は [johnny-shaman/Sign](https://github.com/johnny-shaman/Sign) にあり、仕様書に無い話は [Discussions](https://github.com/johnny-shaman/Sign/discussions) に出てきます。

## 第1章 音を鳴らす

この章は、スピーカーから音を出します。音の装置も「窓口」で、WAV ファイルの音と、高さを指定したピーという音の 2 通りを鳴らせます【拡張】。

### レシピ1 音階とチャイムを鳴らす

**やりたいこと**: `chime.wav` を鳴らし、続けてド・ミ・ソ・高いドの 4 つの音を順に鳴らします。

コードは、配布物の `sound_demo.sn` の先頭の説明を省いたものです。`chime.wav` は同じフォルダに置きます。

```
SND : 0x9800000
TMR : 0x9200000
NAME : 0x600000

seq2 : a b ? b
seq3 : a b c ? c
seq4 : a b c d ? d
seq5 : a b c d e ? e

`待つ(ミリ秒)`
wait : ms ? (TMR + 4) # ms

`名前 chime.wav を置いて鳴らす。鳴り終わりまで待つ`
chime : z ? seq5 ((NAME + 0) # 99) ((NAME + 4) # 104) ((NAME + 8) # 105) ((NAME + 12) # 109) (seq5 ((NAME + 16) # 101) ((NAME + 20) # 46) ((NAME + 24) # 119) ((NAME + 28) # 97) ((NAME + 32) # 118))
play : z ? seq4 ((SND + 0) # NAME) ((SND + 4) # 9) ((SND + 0x14) # 1) (wait 700)

`1 つの音を鳴らして、鳴り終わりまで待つ`
note : f ms ? seq5 ((SND + 8) # f) ((SND + 0x0C) # ms) ((SND + 0x14) # 2) (wait (ms + 30)) 0

seq5 (chime 0) (play 0) (note 262 300) (note 330 300) (seq2 (note 392 300) (note 523 600))
```

`sound_demo.sn` として保存し、鳴らす内容を画面に書くだけの練習用の音(`--sound=fake`)を付けて実行します。

```
python3 sign_interp.py sound_demo.sn --sound=fake
```

実行結果は次のとおりです。`[sound]` の 5 行は標準エラーに、最後の `0` は標準出力に出ます。

```
[sound] play chime.wav
[sound] tone 262Hz 300ms
[sound] tone 330Hz 300ms
[sound] tone 392Hz 300ms
[sound] tone 523Hz 600ms
0
```

**ひとこと**: 音の窓口は、メモリの番地 `0x9800000` から始まります【拡張】。ファイルの名前を置いた番地(`+0x00`)と長さ(`+0x04`)、音の高さ(Hz、`+0x08`)、音の長さ(ミリ秒、`+0x0C`)を書いてから、命令の番地(`+0x14`)に `1` を書くとファイルを鳴らし(PLAY)、`2` を書くと指定の高さの音を鳴らします(TONE)【拡張】。262、330、392、523 Hz は、およそド・ミ・ソ・高いドの高さです。

鳴らし始めたらすぐ戻るので、鳴り終わるまでの時間は、タイマーの窓口(`0x9200000` の `+4`)で待っています(`wait`)【拡張】。ファイルの名前は Sign の文字列をそのまま渡せないため、`chime.wav` の 9 文字を 1 文字ずつ番地に書き(c が 99、h が 104、…)、長さに `9` を書いています【拡張】。最後の `0` は、最後の式 `note 523 600` の値です。最後の式の値を画面に出すのは【実装】です。

**気をつける点** `--sound` を付けないと、何も起きず `0` とだけ出ました【実装】。`--sound=fake` の行は標準エラーに出るので、標準エラーを捨てると `0` だけが残ります。名前を `chime.wax` に変えると、`play` の行は出ず、エラーの文も出ませんでした。ファイルを鳴らせたかどうかは、窓口の結果の番地(`+0x18`)で確かめる作りですが、この本ではその値を見ていません【拡張】。

**確かめていないこと** 実際に音が鳴ること、音量(`+0x10`)、止める命令(`3`)、鳴っているかを読む番地(`+0x1C`)は、確かめていません。`--sound` だけを付けて実際に鳴らすには、Linux では `paplay` などの再生コマンドが要る、とファイルの先頭の説明にあります。確かめたパソコンでは `--sound` を付けても何も出ず、音は聞けませんでした。

## 第2章 LED の明るさを変える

この章は、『動くレシピ集』のレシピ10(LED の点滅)の続きです。LED を点ける・消すだけでなく、明るさを段々に変えます【拡張】。

### レシピ2 LED をゆっくり明るく・暗くする

**やりたいこと**: GPIO17 につながる LED を、呼吸するように 2 秒で一往復、明るくして暗くします。つなぎ方はレシピ10と同じです(GPIO17 ── 330Ω ── LED ── GND)。

明るさは PWM で変えます。PWM は、点いたり消えたりを速く繰り返し、点いている割合で明るさを決める方法です。コードは、配布物の `led_pwm.sn` の先頭の説明を省いたものです。

```
GPIO : 0x9500000
LED_PIN : 17
TICK_MS : 20
PHASE : 0x500000
tm_every : 0x9200010

seq2 : a b ? b
seq3 : a b c ? c

`PWM の明るさの番地 = GPIO + 0x200 + 4 × ピン。周波数の番地 = GPIO + 0x300 + 4 × ピン(既定 1000Hz)`
duty : n v ? (GPIO + (0x200 + (4 * n))) # v

`位相 0〜99 を 三角波(0 → 1000 → 0)にする。50 を頂点にして、どちらへも 20 ずつ`
tri : p ?
	p < 50 : p * 20
	(100 - p) * 20

init : z ? seq3 (PHASE # 0) (tm_every # TICK_MS) (duty LED_PIN 0)

on_timer : id ?
	(PHASE # (((@PHASE) + 1) % 100)) : duty LED_PIN (tri (@PHASE))
	0

tick : z ? 0
```

`led_pwm.sn` として保存します。このプログラムは、[第3巻](03_draw-and-game.md)で使ったゲーム機(`sign_console.py`)で動かします【拡張】。本当の実機では `--display=null --gpio` で動かし、止めるのは Ctrl+C です。ここでは練習用の `--gpio=fake` を付け、実際の時間を待たずにこまを進める `--timer=virtual` で、130 こま(約 2.2 秒分)だけ走らせました。

```
python3 sign_console.py led_pwm.sn --display=null --gpio=fake --timer=virtual --frames=130 --fps=60
```

明るさが変わるたびに、次の行が標準エラーに出ます【拡張】。全部で 104 行出ましたので、中を省いて載せます。

```
[gpio] 17 pwm 0% 1000Hz
[gpio] 17 pwm 2% 1000Hz
[gpio] 17 pwm 4% 1000Hz
  …(2% ずつ増える)
[gpio] 17 pwm 98% 1000Hz
[gpio] 17 pwm 100% 1000Hz
[gpio] 17 pwm 98% 1000Hz
  …(2% ずつ減る)
[gpio] 17 pwm 2% 1000Hz
[gpio] 17 pwm 0% 1000Hz
[gpio] 17 pwm 2% 1000Hz
  …(ここからもう一往復)
```

**ひとこと**: 明るさの番地は `GPIO + 0x200 + 4 × ピン番号` で、ここへ 0 から 1000 を書きます(0 が消灯、1000 が最大)【拡張】。結果の `%` は、書いた値を 10 で割ったものです(値 20 が 2%)。周波数の番地は `GPIO + 0x300 + 4 × ピン番号` で、既定は 1000 Hz です【拡張】。

`tm_every # 20` で「20 ミリ秒ごとに `on_timer` を呼ぶ」と決め、呼ばれるたびに位相(`PHASE`)を 1 進めます。`tri` が位相 0〜99 を「0 → 1000 → 0」の三角の形に直すので、100 回で 1 往復、つまり 2 秒です。位相は関数の外に残す必要があるので、[第3巻](03_draw-and-game.md)と同じくメモリの番地(`0x500000`)に置いています。`#` と `@` は仕様にある演算子です【仕様】。

**気をつける点** このプログラムは画面を使いませんが、ゲーム機の約束で `tick` が要るため、何もしない `tick : z ? 0` を置いています。消すと「エラー: tick が定義されていません」と出て止まりました。`--gpio` を付けないと、明るさを書いても何も起きず、エラーも出ませんでした【実装】。

**確かめていないこと** 実際の Raspberry Pi と LED で、本当に細かく明るさが変わることは、確かめていません。周波数を変える書き方も、試していません。

## 第3章 I2C と SPI

I2C と SPI は、センサーやメモリ IC などの部品と話す、よく使われる配線の決まりです。『動くレシピ集』のレシピ11の温湿度センサーも、I2C でつながる部品です。この章の装置は、どちらも「窓口」の形です【拡張】。

### レシピ3 I2C でつないだ部品を探す

**やりたいこと**: I2C の線につないだ部品のうち、応答したもののアドレスを 16 進で一行ずつ出します(Linux の `i2cdetect` と同じことです)。

コードは、配布物の `i2c_scan.sn` の先頭の説明を省いたものです。`std.sn` は同じフォルダに置きます。

```
`std.sn`@~

I2C : 0x9600000
TMP : 0x600000

`アドレス a に応答があるか(あれば 0)`
probe : a ? seq3 ((I2C + 0) # a) ((I2C + 0x14) # 4) (@(I2C + 0x18))

found : a ? seq4 (print `0x`) (str_hex TMP a) (println_mem TMP) 0
scan : a ?
	a > 0x77 : 0
	(probe a) = 0 : seq2 (found a) (scan (a + 1))
	scan (a + 1)

seq2 : a b ? b
scan 0x03
```

`i2c_scan.sn` として保存し、練習用の部品をアドレス `0x48` と `0x50` に置いて(`--i2c=fake:0x48,0x50`)実行します。

```
python3 sign_interp.py i2c_scan.sn --i2c=fake:0x48,0x50
```

実行結果は次のとおりです。

```
0x48
0x50
0
```

**ひとこと**: I2C の窓口は `0x9600000` から始まり、相手のアドレス(`+0x00`)を書いてから命令の番地(`+0x14`)に命令の番号を書き、結果を `+0x18` から読みます【拡張】。命令の番号は、`1` が送る、`2` が読む、`3` が送ってから読む、`4` が「その相手が応答するか」の確認(PROBE)です【拡張】。応答すると結果は `0`、しないと負の数(相手がいないときは「6」を負にした数)です。このうち、このレシピで結果を見たのは応答の `0` だけです。

`scan` は、アドレス `0x03` から `0x77` までを順に調べます。`str_hex` と `println_mem` は `std.sn` の関数です【拡張】。最後の `0` は最後の式の値です【実装】。

**気をつける点** `str_hex` は桁をそろえません。練習用の部品を `0x03` と `0x77` に置くと、`0x3` と `0x77` と出ました。`--i2c` を付けないと、応答が一つもなくて `0` とだけ出ます。部品がつながっていないときとまったく同じ表示なので、「何も見つからない」ときは、オプションを付け忘れていないかも見てください【実装】。

**確かめていないこと** 本物の Raspberry Pi と部品は、確かめていません。本物で使うには、`raspi-config` で I2C を有効にし、`--i2c` だけを付けて実行する、とファイルの先頭の説明に書いてありますが、試していません。

### レシピ4 SPI で自分を診断する

**やりたいこと**: SPI で 4 バイトを送り、返ってきた 4 バイトを 10 進で出します。送る線(MOSI)と受ける線(MISO)を 1 本につなぐと、送った値がそのまま戻ってくるので、配線と装置の自己診断になります。

コードは、配布物の `spi_loopback.sn` の先頭の説明を省いたものです。

```
`std.sn`@~

SPI : 0x9700000
BUF : 0x600000

seq3 : a b c ? c
seq5 : a b c d e ? e

fill : z ? seq5 ((BUF + 0) # 1) ((BUF + 4) # 2) ((BUF + 8) # 3) ((BUF + 12) # 4) 0
xfer : z ? seq5 ((SPI + 0) # BUF) ((SPI + 4) # 4) ((SPI + 0x08) # 1000000) ((SPI + 0x14) # 1) (@(SPI + 0x18))
show : i ?
	i > 3 : println ``
	seq3 (print_int (@(BUF + (4 * i)))) (print ` `) (show (i + 1))

seq3 (fill 0) (xfer 0) (show 0)
```

`spi_loopback.sn` として保存し、送ったものをそのまま返す練習用の SPI(`--spi=fake`)を付けて実行します。

```
python3 sign_interp.py spi_loopback.sn --spi=fake
```

実行結果は次のとおりです(最後の数のあとに空白があります)。

```
1 2 3 4 
0
```

**ひとこと**: SPI の窓口は `0x9700000` から始まり、送るバッファの番地(`+0x00`)とバイト数(`+0x04`)、クロック(Hz、`+0x08`)を書き、命令の番地(`+0x14`)に `1`(TRANSFER)を書くと、送ると同時に受け取った内容で同じバッファを置き換えます【拡張】。バッファは 1 バイトを 1 語(4 バイト刻み)で並べるので、`BUF + 4 × i` を読んでいます。練習用の SPI を `--spi=fake:inv` にすると、全ビットを反転して返すので、`254 253 252 251` と出ました【拡張】。

**気をつける点** `--spi` を付けないで実行すると、やはり `1 2 3 4` と出て、最後の値だけが `0` ではなく `__` になりました。これは、先に `fill` がバッファに書いた値をそのまま読んでいるからです。つまり、この見本は「`1 2 3 4` と出たから成功」とは言えません。最後の値が `0` であること(送信が実際に行われたこと)もあわせて見ます【実装】。また、`--spi` だけを付けても、確かめたパソコンでは `1 2 3 4` と `0` が出ました。SPI のライブラリ(`spidev`)が無いと練習用に切り替わる、とファイルの先頭の説明にあります。

**確かめていないこと** 本物の SPI と、線をつないだとき・つないでいないときの違いは、確かめていません。ファイルの先頭の説明では、つなぐのは MOSI(GPIO10)と MISO(GPIO9)、線がつながっていないと `0 0 0 0` となります。

## 第4章 ファイルとキー

この章は、ファイルを読み書きし、キーの出来事を自分で読みます。どちらも「窓口」です【拡張】。

### レシピ5 ファイルに書いて、読み直す

**やりたいこと**: `out.txt` を作って文字を書き、開き直して読み、標準出力へ出して、ファイルの大きさを答えます。

コードは、配布物の `sys_demo.sn` の先頭の説明を省いたものです。

```
SYS : 0x9400000
nr : SYS + 0x00
a0 : SYS + 0x04
a1 : SYS + 0x08
a2 : SYS + 0x0C
go : SYS + 0x14
ret : SYS + 0x18

seq3 : a b c ? c
seq4 : a b c d ? d
seq6 : a b c d e f ? f

PATH : 0x600000
BUF : 0x610000
BUF2 : 0x620000

sys : n x y z ? seq6 (nr # n) (a0 # x) (a1 # y) (a2 # z) (go # 1) (@ret)

putstr : base s i ?
	i >= ||s|| : 0
	seq3 ((base + (i * 4)) # ((s ' i) - 0u0)) (putstr base s (i + 1)) 0

`1. out.txt を作り直して 16 バイト書く(15 文字 + 改行)`
write_it : fd ? seq3 (sys 2 fd BUF 16) (sys 4 fd 0 0) (read_it (sys 3 PATH 7 0))
`2. 開き直して読み、標準出力へ出す`
read_it : fd ? show_it fd (sys 1 fd BUF2 64)
show_it : fd n ? seq3 (sys 2 1 BUF2 n) (sys 4 fd 0 0) (sys 7 PATH 7 0)

main : z ? seq4 (putstr PATH `out.txt` 0) (putstr BUF `hello from Sign` 0) ((BUF + 60) # 10) (write_it (sys 3 PATH 7 1))

main 0
```

`sys_demo.sn` として保存し、ファイルの装置を入れて(`--sys`)実行します。ファイルは、実行したフォルダの中だけ読み書きできます。

```
python3 sign_interp.py sys_demo.sn --sys
```

実行結果は次のとおりです。実行したフォルダに `out.txt` ができ、大きさは 16 バイトでした。

```
hello from Sign
16
```

**ひとこと**: ファイルの窓口は `0x9400000` から始まり、システムコールの番号(`+0x00`)と引数 3 つ(`+0x04`、`+0x08`、`+0x0C`)を書いて、命令の番地(`+0x14`)を書くと実行され、結果を `+0x18` から読みます【拡張】。`sys` は、この手順を 1 つの関数にしたものです。結果が負の数ならエラーです。このレシピで使った番号は、次の 5 つです【拡張】。

| 番号 | 名前 | 引数 | 結果 |
| --- | --- | --- | --- |
| 1 | READ | fd、バッファ、バイト数 | 読んだバイト数 |
| 2 | WRITE | fd、バッファ、バイト数 | 書いたバイト数(fd 1 が標準出力) |
| 3 | OPEN | 名前のバッファ、長さ、モード(0 読む、1 作り直して書く) | fd(3 以上) |
| 4 | CLOSE | fd | 0 |
| 7 | SIZE | 名前のバッファ、長さ | ファイルの大きさ(バイト) |

バッファは 1 バイトを 1 語(4 バイト刻み)で並べるので、`putstr` が Sign の文字列を 1 文字ずつバッファへ写しています。`hello from Sign` の 15 文字に、`(BUF + 60) # 10`(改行)を足して 16 バイトです。最後の `16` は、最後の式 `sys 7 PATH 7 0`(ファイルの大きさ)の値で、画面に出すのは【実装】です。

**気をつける点** `--sys` を付けないと、何も起きず `__` とだけ出ました【実装】。フォルダの外を指す名前(`../x` など)で開くと、結果は `-13` でした【拡張】。`OPEN` のモード `1` は「作り直して」書くことなので、同じ名前のファイルがあると中身は消えます。

**確かめていないこと** 標準入力からの読み込み(fd 0)、時刻(番号 5 と 6)、足して書くモード(`2`)、大きなファイルは、試していません。`--sys=フォルダ` で別のフォルダを指せる、とファイルの先頭の説明に書いてありますが、これも試していません。

### レシピ6 キーの出来事を自分で読む

**やりたいこと**: 右キーで四角を右へ 2 画素ずつ動かし、`q` を押すと終わります。[第3巻](03_draw-and-game.md)の `on_key` は、ゲーム機が出来事を読んで呼んでくれました。ここでは、出来事の行列を自分で読みます。

コードは、配布物の `keys.sn` の先頭の説明を省いたものです。

```
gfx : 0x9100000
timer : 0x9200000
inp : 0x9300000

color : gfx + 0x08
px : gfx + 0x0C
py : gfx + 0x10
cmd : gfx + 0x14
arg0 : gfx + 0x18
arg1 : gfx + 0x1C
sleep : timer + 0x04
count : inp + 0x00
etype : inp + 0x04
ecode : inp + 0x08
pop : inp + 0x14

seq2 : a b ? b
seq3 : a b c ? c
seq8 : a b c d e f g h ? h

clear : c ? seq2 (color # c) (cmd # 2)
rect : x y w h c ? seq8 (color # c) (px # x) (py # y) (arg0 # w) (arg1 # h) (cmd # 5) 0 0
present : z ? cmd # 3

`--- キーが押された出来事 (種類 1) の符号に応じて位置を変える ---`

step : code x ?
	code = 0x1C : x - 2
	code = 0x1D : x + 2
	x

`--- 出来事を捨てて続きを読む。先に引数 (次の x) を評価するので、捨てる前の先頭を使える ---`

popped : nx ? seq2 (pop # 0) (drain nx)

`--- 行列を空になるまで読む。q (113) か 閉じる (6) なら -1 を返して終わる ---`

drain : x ?
	@count = 0 : x
	@etype = 6 : seq2 (pop # 0) (0 - 1)
	@etype = 1 & @ecode = 113 : seq2 (pop # 0) (0 - 1)
	@etype = 1 : popped (step @ecode x)
	seq2 (pop # 0) (drain x)

loop : x ?
	x < 0 : @px
	seq3 (clear 0) (rect x 4 6 6 0xFFFFFF) (present 0) : seq2 (sleep # 16) (loop (drain x))

loop 10
```

`keys.sn` として保存します。本当は窓を開いて遊びますが、ここでは窓を開かず、PNG を 1 こまずつ保存する練習用の画面と、キーの台本で確かめました。台本は、右キー(番号 29)を 2 回押して離し、最後に `q`(番号 113)を押すものです。このプログラムは[第3巻](03_draw-and-game.md)のゲーム機ではなく `sign_interp.py` で動かします。

```
python3 sign_interp.py keys.sn --display=png:ky{n}.png:64x32 --timer=virtual --input=100:kd:29,110:ku:29,200:kd:29,210:ku:29,300:kd:113,310:ku:113
```

`ky1.png` から `ky19.png` の 19 枚ができ、画面には `14` と出ました。できた PNG を読んで、白い四角の左端の x を測った結果は、次のとおりです。

| 枚 | 白い四角の左端の x |
| --- | --- |
| 1 〜 7 枚目 | 10 |
| 8 〜 13 枚目 | 12 |
| 14 〜 19 枚目 | 14 |

**ひとこと**: 入力の窓口は `0x9300000` から始まり、たまっている出来事の数(`+0x00`)、先頭の出来事の種類(`+0x04`)と符号(`+0x08`)を読み、`+0x14` に書くと先頭を捨てます【拡張】。種類は、`1` がキーを押した、`2` がキーを離した、`6` が窓を閉じたです【拡張】。`drain` は、行列が空になるまで先頭を読んでは捨て、キーを押した出来事だけで `step` を呼び、`q` なら `-1` を返して終わります。キーを離した出来事は読み飛ばします。左右キーの番号は 28 と 29(16 進で `0x1C`、`0x1D`)です。最後の `14` は、`loop` が終わるときに返す `@px`、つまり最後に描いた四角の x です。画面に出すのは【実装】です。[第3巻](03_draw-and-game.md)の「押すたび 1 回」の `on_key` と違い、こちらは自分で行列を読むので、どの種類の出来事を拾うかを自分で決められます。

**確かめていないこと** 窓を閉じる出来事(`6`)と、マウスの出来事(`3` から `5`)は、このレシピでは試していません。本物の窓での操作感も、確かめていません。

## 付録 実行するコマンドの一覧

この巻のレシピで使った実行方法をまとめました。すべて既定のモードです。

| レシピ | コマンド |
| --- | --- |
| 1 | `python3 sign_interp.py sound_demo.sn --sound=fake` |
| 2 | `python3 sign_console.py led_pwm.sn --display=null --gpio=fake --timer=virtual --frames=130 --fps=60` |
| 3 | `python3 sign_interp.py i2c_scan.sn --i2c=fake:0x48,0x50` |
| 4 | `python3 sign_interp.py spi_loopback.sn --spi=fake` |
| 5 | `python3 sign_interp.py sys_demo.sn --sys` |
| 6 | `python3 sign_interp.py keys.sn --display=png:ky{n}.png:64x32 --timer=virtual --input=100:kd:29,110:ku:29,200:kd:29,210:ku:29,300:kd:113,310:ku:113` |

装置とオプションの対応を、まとめておきます。すべて【拡張】です。

| 装置 | 基点の番地 | オプション | 練習用 |
| --- | --- | --- | --- |
| ファイル | `0x9400000` | `--sys` | — |
| 入力 | `0x9300000` | `--input=台本` | 台本そのもの |
| GPIO(明るさを含む) | `0x9500000` | `--gpio` | `--gpio=fake` |
| I2C | `0x9600000` | `--i2c` | `--i2c=fake:アドレス,…` |
| SPI | `0x9700000` | `--spi` | `--spi=fake`、`--spi=fake:inv` |
| 音 | `0x9800000` | `--sound` | `--sound=fake` |

共通の約束が 3 つあります。

- `std.sn` は、レシピ3 と レシピ4 で使います。プログラムと同じフォルダに置きます。`chime.wav` はレシピ1 で、同じフォルダに置きます。
- 装置のオプション(`--sound`、`--gpio`、`--i2c`、`--spi`、`--sys`)は、付けないと、この巻のどのレシピでも、エラーにもならず、装置が無いまま動きます。結果が空でも、実際に失敗しているとは限らず、つけ忘れかもしれません。
- 実機で動かすときは、`fake` を外して `--gpio`、`--i2c`、`--spi`、`--sound` を付けます。この巻では実機で確かめていません。
