## はじめに

この本は、Sign で何かを作りたい人が、やりたいことから引ける小さなレシピ集です。文法の説明は『Sign入門』に任せ、ここでは動くコードと結果を並べます。第1章から第4章にレシピを 11 本載せています。

各レシピは「やりたいこと、全コード、実行結果、ひとこと」の順です。コードは実際に動かして結果を取っています。実行は、既定のモードで行いました。確かめた版は「alpha1 実装 2026-11-06 00:50 JST」です。

コマンドは、bash で打つ形で書いています。確かめたのは Linux の上だけで、Windows や macOS では試していません。

結果の出どころは、入門書と同じ3つの印で分けます。

- **【仕様】** 配布された仕様書に書かれている動作です。
- **【実装】** `sign_interp.py` がそう動くだけで、仕様書に見つからない動作です。別の処理系では同じになるとは限りません。
- **【拡張】** 仕様に無い、この実装に添えた道具(`std.sn` など)です。

印の無い記述は、ゲームやツールのルール、動かして見た結果の説明です。仕様書との一致を示すのは【仕様】の印だけです。Sign の資料は [johnny-shaman/Sign](https://github.com/johnny-shaman/Sign) にあり、仕様書に無い話は [Discussions](https://github.com/johnny-shaman/Sign/discussions) に出てきます。

## 第1章 標準入力を読む

標準入力の読み書きには、`std.sn` の `read_line` と `println_int` を使います。どちらも【拡張】で、仕様にはありません。`std.sn` は `sign_interp.py` と同じフォルダに置き、プログラムをそのフォルダから実行します。

### レシピ1 入力の行数を数える

**やりたいこと**: 標準入力の行数を出します。空行も 1 行と数えます。

```
`std.sn`@~

LINE : 0x600000

count : n ? count2 n (read_line LINE 256)
count2 : n len ?
	len < 0 : n
	count (n + 1)

println_int (count 0)
```

`count_lines.sn` として保存し、次のように実行します。

次のコマンドは Sign ではなく、入力を流し込む bash(シェル)のコマンドです。`printf` が文字列を作り、`|` で `python3 sign_interp.py` に渡します。手で入力しても同じ結果になります。

```
printf 'a\nb b\n\nccc\n' | python3 sign_interp.py count_lines.sn
```

実行結果は次のとおりです。

```
4
0
```

**ひとこと**: `read_line` は 1 行をメモリの `LINE` に読み、読んだ文字数を返します。空行は 0 で、入力が終わって何も読めないと -1 を返します【拡張】。`len < 0 : n` の行が終わりの判定で、条件が成り立てばその行の値を返し、立たなければ次の行へ進みます。最後の `0` は、`println_int` が返す値です。プログラムの最後の式の値は、仕様書の例でも「評価結果」として示されています【仕様】。それを実行時に画面へ出すことは、この実装の動きです【実装】。表示される末尾の `0` は、計算の結果ではなく、この表示の副産物と読んで構いません。

### レシピ2 整数の統計を出す

**やりたいこと**: 1 行に 1 つ、整数を読んで、個数・合計・平均・最小・最大・中央値を出します。整数でない行は読み飛ばします。

コードは、次の 3 つの部分でできています。

- **読む(****`load`****、****`load2`****、****`load3`****)**: 1 行ずつ読み、整数だけをメモリの `N` から順に並べます。終わりまで読んだとき、並べた個数を返します。
- **出す(****`row`****、****`report`****)**: 並べた値を足したり並べ替えたりして、個数・合計・平均・最小・最大・中央値を順に印刷します。
- **つなぐ(最後の行)**: `report (load 0)` で、読んでから出します。

```
`std.sn`@~

N : 0x500000
LINE : 0x600000

load : n ? load2 n (read_line LINE 64)
load2 : n len ?
	len < 0 : n
	((str_trim LINE) >= 0) & ((str_is_int LINE) = 1) : load3 n
	load n
load3 : n ?
	(arr_set N n (str_to_int LINE)) : load (n + 1)

row : label v ? seq3 (print label) (println_int v) 0

report : n ?
	n = 0 : println `数がありません`
	seq9 (row `個数    : ` n) (row `合計    : ` (arr_sum N n)) (row `平均    : ` ((arr_sum N n) / n)) (arr_sort N n) (row `最小    : ` (arr_get N 0)) (row `最大    : ` (arr_get N (n - 1))) (row `中央値  : ` (arr_get N (n / 2))) (println `(平均は整数。0 の方へ丸める)`) 0

report (load 0)
```

上のコードは配布物の見本 `std_demo.sn` です。次のように実行します。

次のコマンドも Sign ではなく、入力を流し込む bash(シェル)のコマンドです。`printf` で作った文字列を、`|` で `python3 sign_interp.py` に渡しています。

```
printf '5\n3\n8\nabc\n 10 \n-2\n' | python3 sign_interp.py std_demo.sn
```

実行結果は次のとおりです。

```
個数    : 5
合計    : 24
平均    : 4
最小    : -2
最大    : 10
中央値  : 5
(平均は整数。0 の方へ丸める)
0
```

**ひとこと**: 入力をいったんメモリの連続した番地(`N`)に並べ、`arr_sort` で並べ替えてから最小・最大・中央値を取り出しています。`arr_set`、`arr_sum`、`arr_sort`、`str_to_int` はすべて `std.sn` の【拡張】です。平均は整数の割り算で、`24 / 5` が `4` になりました【仕様】(第8巻で、type_system.md と照らしました)。入力が空のときは「数がありません」を出します。実行結果の最後の `0` は、レシピ1と同じ表示の副産物です。

## 第2章 List を集計する

この章のコードは `std.sn` を使わず、言語の機能だけで書いています。実行結果は、念のため `--strict` でも確かめ、同じでした。ただし【仕様】value_spec.md の V9 は「定義でない行の値はファイルでは捨てる」と書き、【実装】この実装は 2026-11-04 22:40 の版から --strict でそれに合わせたので、--strict で走らせると最後の行の値は画面に出ません(print などで出した文字は出ます)。ここで「同じ」と書いたのは、値を取り出して既定と比べた結果です。

### レシピ3 合計・個数・平均・最大を出す

**やりたいこと**: 数の List `[3 9 4 1 7]` の合計・個数・平均・最大を一度に出します。

```
sum : [h ~t] ? h + (sum t)
len : [h ~t] ? 1 + (len t)
max_of : [h ~t] ?
	!t : h
	h > (max_of t) : h
	max_of t
xs : [3 9 4 1 7]
[(sum xs) (len xs) ((sum xs) / (len xs)) (max_of xs)]
```

実行結果は次のとおりです。

```
[24, 5, 4, 9]
```

**ひとこと**: `[h ~t]` は、List を先頭の `h` と残りの `t` に分けて受け取る仮引数です。`!t : h` は「残りが空なら `h`」という終わりの行です。`[h ~t]` で List を分ける書き方と、`!xs : 0` のように空を見分ける行は、`reference.md` の List の長さを求める例にあります【仕様】。なお `function_guide.md` は、再帰の終わりは `!xs` で書かずに完全性公理に任せるのがよい、とも述べています。この本で `!t` を使っているのは、最後の要素を先に返すためです。`sum` と `len` は `!t` の行を書いていません。最後の要素で空の List を渡すとその呼び出しは `__` になり、算術では `__` が単位元(`__ + 3` は `3`)なので、答えが変わらないからです【仕様】(`unit.md`)。既定と `--strict` で、`sum` は `3` を返しました(1 要素の List を渡した場合)。平均は `24 / 5` なので `4` になりました【仕様】。小数を出す話はここでは扱いません。

**もう一つの書き方**: 足し算や掛け算だけなら、再帰を書かずに `[+]` で畳めます。`[+] 3 9 4 1 7` は `3 + 9 + 4 + 1 + 7` と同じです。

```
[+] 3 9 4 1 7
```

実行結果は次のとおりです。

```
24
```

**ひとこと**: `[op] x1 … xn` は、`x1 op … op xn` と同じ読みです【仕様】(`coproduct_spec.md` の R31。設計者の答えは「演算子表の結合の向きどおりに並べた物と同じ」)。`[*] 1 2 3 4` は `24`、`[-] 10 3 2` は左から `(10 - 3) - 2` で `5` です。`^` だけは右から結ぶので、`[^] 2 3 2` は `512` です。`_` を実引数に書く形も中置と同じ読みで、`[+] 1 _ 3` は `4` です。

**実装の読み**: この本のレシピは既定のモードです。`[+] 3 9 4 1 7` と `[*] 1 2 3 4`、`[-] 10 3 2`、`[^] 2 3 2` の答え(`[^] 2 3 2` は `512`)は、既定のモードで実際に走らせて確かめました。仕様と食い違うのは次の一点です【実装】。`[+] 1 _ 3` は、既定のモードが G5 で止めます。`--strict` だけが `4` を返しました。この本のレシピは `_` を書いた畳みを使いません。比べる記号の畳みは、`[<] 1 2 3` が `1` を返すなど、走らせた範囲では既定のモードも仕様と同じ答えでした。ただし、この本のレシピでは使わないので、広くは確かめていません。なお、以前の版の既定のモードは `[^] 2 3 2` を左から畳んで `64` を返しましたが、今は右から結んで `512` です。

### レシピ4 条件に合う数だけを足す

**やりたいこと**: 1000 未満の自然数のうち、3 または 5 の倍数だけを足します。

```
v : n ?
	n % 3 = 0 : n
	n % 5 = 0 : n
	0
sum : n acc ?
	n = 0 : acc
	sum (n - 1) (acc + (v n))
sum 999 0
```

実行結果は次のとおりです。

```
233168
```

**ひとこと**: `v` は「条件に合うならその数、合わなければ 0」を返す関数です。`sum` は累積引数 `acc` を渡していく末尾再帰です。行を上から順に試し、最初に条件が成り立った行の値を返すのは仕様どおりです。最後の `0` の行は、条件を書かない「それ以外」の行です。

### レシピ5 構造体を年齢順に並べる

**やりたいこと**: 名前と年齢を持つ 4 人を、年齢の小さい順に並べます。構造体そのものを組み替えるのではなく、並べた順を「添字(何番目か)の List」として作ります。

```
ann : [
	name : `Ann`
	age : 31
]
bob : [
	name : `Bob`
	age : 25
]
cy : [
	name : `Cy`
	age : 40
]
dee : [
	name : `Dee`
	age : 28
]
people : [ann bob cy dee]
age_at : i ? (people ' i) ' age
name_at : i ? (people ' i) ' name
ins : i [h ~t] ?
	(age_at i) <= (age_at h) : i , h , t~
	!t : h , i
	h , (ins i t)~
isort : k n acc ?
	k = n : acc
	isort (k + 1) n (ins k acc)
order : isort 1 4 0
[order (name_at (order ' 0)) (name_at (order ' 3))]
```

実行結果は次のとおりです。

```
[[1, 3, 0, 2], `Bob`, `Cy`]
```

**ひとこと**: `order` は年齢順の添字です。`bob`(25)、`dee`(28)、`ann`(31)、`cy`(40) の順に、添字 1、3、0、2 が並んでいます。先頭の名前は `Bob`、最後は `Cy` です。`ins` は、並び終えた添字の List に新しい添字 `i` を挿し込みます。結果を組み立てる再帰は添字(数)だけで行い、名前は最後に一件ずつ引いています。この書き方の理由は次の「書き方の決まり」で説明します。人数は 2 人以上を前提にしています。なお、`isort 1 4 0` の `4` は人数です。

### この章でつまずきやすい点

レシピを試している途中で、次の 2 点で思いどおりに動かないことがありました。どちらも、ソートのような再帰で List を組み立てるときに、つまずきやすい点です。

- **要素が 1 つの List は、その要素と同じです【仕様】**。`list_model.md` に「1要素リストとスカラーは同型」とあります。構造体 `ann`(`name` と `age` を持つ)を 1 つだけ入れた `[ann]` は `ann` と同じなので、`[ann] ' age` は `31` を返します。`[ann] ' 0` は先頭の要素ではなく `__` になりました【実装】。構造体の List を再帰で辿ると、最後の要素のところで使い方が変わります。
- **空の List ****`[]`**** は、関数に渡せません【仕様】**。`list_model.md` に「空の器は関数へ渡せない」とあり、既定値の無い仮引数が空を受け取ると、完全性公理(`unit.md`、`type_system.md` の§3.4)で呼び出しごと `__` になる(`f : x ? 1` に `[]` を渡すと `__`)と書かれています。`ins 3 []` も `__` になり、既定と `--strict` で同じ結果でした。同じ箇所は、蓄積の種を空にせず、最初の要素から始めるよう勧めています。

### List を再帰で扱う書き方の決まり

前節の 2 点を避けるために、この本のレシピでは次の 4 つを決まりにします。

1. List を再帰で辿る関数は `[h ~t]` で受け、`!t` の行で最後の 1 要素を先に片付けます(`max_of`、`ins`)。空の List を再帰に渡さないためです。空の器は関数へ渡せないという仕様の注意書きに沿っています【仕様】。
2. 累積引数は、最初から 1 要素以上入れて始めます(`isort 1 4 0` の `0`)。結果は `,` と `~` で組み立てます。`list_model.md` も「蓄積は最初の要素を種にする」としています【仕様】。
3. 構造体や文字列の List を、再帰で組み立てません。順番は添字(数)の List で作り、名前などは最後に `(people ' i) ' name` で引きます。文字列は文字の List なので(`reference.md`)、文字列を 1 つだけ含む結果に `~` を使うと文字に分かれます【仕様】。
4. 構造体の List は 2 件以上を前提にします。1 件だけの List はその構造体と同じになります【仕様】。

この 4 つは、仕様書と突き合わせて確かめました。結果は `list_model.md`、`unit.md`、`reference.md` の記述と一致しています。ただし、`[ann] ' 0` が `__` になる点だけは、仕様書で確かめていない【実装】の結果です。ただし、ここで書いた「こう書く」という選び方自体は、仕様が指示しているわけではありません。

## 第3章 CSV を読む

この章のコードも `std.sn` を使わず、配布物の `robust_csv.sn` をもとにしています。欄が欠けていても、文字が混じっていても、行が足りなくても、止まらずに「読めなかった」欄だけを飛ばして集計します。

### レシピ6 行から欄の数を読む

**やりたいこと**: `alice,30,82` のような CSV の 1 行から、k 列目(0 始まり)を数として読みます。読めない欄は、エラーにせず `__` にします。

```
rows : [`alice,30,82` , `bob,x,75` , `carol,,90` , `dave,41` , `eve,28,9z` , `frank,35,100`]

col : s k i c acc bad ?
	i >= ||s|| : fin acc bad
	step s k i c acc bad (s ' i)
step : s k i c acc bad ch ?
	ch = 0u2C : comma s k i c acc bad
	c = k : digit s k i c acc bad ch
	col s k (i + 1) c acc bad
comma : s k i c acc bad ?
	c = k : fin acc bad
	col s k (i + 1) (c + 1) (0 - 1) bad
digit : s k i c acc bad ch ?
	(ch >= 0u30) & (ch <= 0u39) : col s k (i + 1) c (dig acc (ch - 0u30)) bad
	col s k (i + 1) c acc 1
dig : acc d ?
	acc < 0 : d
	(acc * 10) + d
fin : acc bad ?
	bad = 1 : __
	acc < 0 : __
	acc

cell : r k ? col r k 0 0 (0 - 1) 0

cell (rows ' 0) 1
```

実行結果は次のとおりです。

```
30
```

ほかの行と欄でも、最後の行を変えて試しました。

| 呼び出し | 元の欄 | 結果 |
|---|---|---|
| `cell (rows ' 0) 1` | `30` | `30` |
| `cell (rows ' 1) 1` | `x`(文字が混じった欄) | `__` |
| `cell (rows ' 2) 1` | 空の欄 | `__` |
| `cell (rows ' 3) 2` | 行が足りない(欄が無い) | `__` |
| `cell (rows ' 4) 2` | `9z`(文字が混じった欄) | `__` |
| `cell (rows ' 5) 2` | `100` | `100` |

**ひとこと**: `s ' i` は文字列 `s` の i 文字目で、`||s||` は要素数(文字数)です【仕様】。`0u2C` はコンマ、`0u30` から `0u39` は数字の `0` から `9` で、`0u` の後ろに 16 進で書くと文字になります【仕様】。状態(何列目を読んでいるか、これまでの桁、文字が混じったか)は、変数を書き換える代わりに引数 `acc`、`bad` として次の呼び出しへ渡しています。`acc` が `-1` のときは「まだ 1 桁も読んでいない」印です。読めなかったときだけ `fin` が `__` を返します。`rows` の要素は `,` で区切っています。

### レシピ7 列ごとの合計と件数を出す

**やりたいこと**: 年齢の列(1)と点数の列(2)について、読めた欄だけの合計と、読めた件数を出します。レシピ6のコードの最後の行 `cell (rows ' 0) 1` を消して、代わりに下のコードを続けます。

```
total : k i acc ?
	i >= ||rows|| : acc
	total k (i + 1) (acc + (cell (rows ' i) k))
count : k i acc ?
	i >= ||rows|| : acc
	count k (i + 1) (acc + ((cell (rows ' i) k) & 1))

[(total 1 0 0) (count 1 0 0) (total 2 0 0) (count 2 0 0)]
```

実行結果は次のとおりです。年齢の合計 134(4 件)、点数の合計 347(4 件)です。

```
[134, 4, 347, 4]
```

**ひとこと**: 読めない欄は `__` ですが、`__ + 3` は `3` になります(`__` は `+` の単位元です)【仕様】。このため、`total` は読めない欄を特別扱いせずに足し算を続けられます。件数は、`& 1` で読めた欄を `1` にして足しています。`&` は左右に `__` が来ると `__` を返し、足し算で消えます【仕様】。左が `__` でなければ `&` は右の値を返す、という読みは、仕様書の例から取れます。`reference.md` の `sum_list : [x ~xs] ? xs & x + (sum_list xs) | x` と `unit.md` §0.2 の `append` は、`xs` が空でないときに `&` の右を評価して、その値を結果にします【仕様】。この読みで、読めた欄の `& 1` は `1` になります。ただし、`&` の返す値を「右辺の値」と書いた条文は見つかりませんでした。関数に `__` を直接渡すと呼び出しごと `__` になる【仕様】ので、`cell` の結果を関数へ渡さず、演算子にだけ渡しています。

## 第4章 機械と話す

メモリの番地に直接書く `#` と読む `@` は、仕様にある演算子です【仕様】。LED やセンサーを動かす GPIO や I2C の「装置」は、仕様に無い、この実装に添えた道具です【拡張】。装置は「特定の番地を読み書きすると、ピンやセンサーが動く」形で使います。この章の装置のレシピは、実機(本物の Raspberry Pi と LED・センサー)では動かしていません。パソコン上の練習モード(本物のピンを使わない)で確かめています。

### レシピ8 メモリに並べて足す

**やりたいこと**: メモリの番地 `0x500000` から 5 語に `10`、`20`、`30`、`40`、`50` を書き、読み直して合計を出します。

```
BUF : 0x500000
set : i v ? (BUF + (i * 4)) # v
get : i ? @(BUF + (i * 4))
sum : i n acc ?
	i >= n : acc
	sum (i + 1) n (acc + (get i))
fill : i n ?
	i >= n : 0
	(set i ((i + 1) * 10)) : fill (i + 1) n
fill 0 5
sum 0 5 0
```

実行結果は次のとおりです。

```
150
```

**ひとこと**: `a # v` は番地 `a` に `v` を書き、成功したときにはその番地を返します【仕様】。返す番地は `__` ではないので、`(set i ...) : fill (i + 1) n` のように「書けたら次へ」を条件の行として書けます。`@a` は番地 `a` を読みます【仕様】。語を 4 番地刻みで置く(`BUF + (i * 4)`)のは、この実装と `std.sn` の約束です【実装】。`0x500000` が使える番地かどうかも、この実装で使える領域の話です【実装】。

### レシピ9 範囲外の書き込みを実行時に見つける

**やりたいこと**: 用意した広さを超えて書いてしまう間違いを、止めて知らせてもらいます。

レシピ8を、最後の 2 行だけ `fill 0 6` と `sum 0 6 0` に変えて `bug.sn` として保存します。5 語(20 番地)しか用意していないのに、第 6 語目を書くことになります。次のように、`--check-bounds` と `--ram` を付けて実行します。

```
python3 sign_interp.py --check-bounds --ram=0x500000:20 bug.sn
```

実行結果は次のとおりです(終了コードは 1)。

```
エラー: bug.sn:2:13: 境界: 書き込みの番地 0x500014 は、装置の帯と --ram で宣言した範囲のどれにも入っていません
     2 | set : i v ? (BUF + (i * 4)) # v
       |             ^
```

**ひとこと**: `--ram=始まり:大きさ` は「ここは使ってよい」と宣言する範囲で、範囲の終わりの先は含みません(0x500000 から 20 番地なら、使えるのは `0x500000` から `0x500013` までです)。この範囲チェックは、`--check-bounds` と `--ram` とも、仕様に無い、この実装の機能です【拡張】。コードの位置は、書き込みの行(2 行目の `#`)を指します。付けずに `bug.sn` を動かすと、範囲外に書いたまま止まらず、`210` を返しました。正しい `fill 0 5` のコードは、同じオプションで `150` を返します。

### レシピ10 LED を点滅させる

**やりたいこと**: GPIO17 のピンを 500 ミリ秒ごとに上げ下げして、LED を点滅させます。

```
GPIO : 0x9500000
LED_PIN : 17
PERIOD : 500
LED : 0x500000
tm_every : 0x9200010

seq2 : a b ? b
seq3 : a b c ? c

pin : n v ? (GPIO + (4 * n)) # v

init : z ? seq3 (LED # 0) (tm_every # PERIOD) (pin LED_PIN 0)

on_timer : id ?
	(LED # (1 - (@LED))) : pin LED_PIN (@LED)
	0

tick : z ? 0
```

パソコンでの練習は、`--gpio=fake` を付けて実行します。本物のピンは使いません。このファイルは配布物の `led_gpio.sn` です。

```
python3 sign_console.py led_gpio.sn --display=null --gpio=fake
```

実行している間、ピンの変化が標準エラーに 500 ミリ秒ごとに出ます(Ctrl+C で止めます)。

```
[gpio] 17 = 0
[gpio] 17 = 1
[gpio] 17 = 0
[gpio] 17 = 1
```

**ひとこと**: ピンの値の番地は `GPIO + 4 × ピン番号` で、ここへ `1` を書くと HIGH、`0` を書くと LOW になります【拡張】。`init` は始めに一度、`on_timer` はアラームが鳴るたびに呼ばれる関数です【拡張】。`tm_every # 500` で「500 ミリ秒ごと」のアラームを頼みます。LED の状態はメモリの番地 `LED` に持ち、`1 - (@LED)` で 0 と 1 を行き来させています。実機では動かしていません。

### レシピ11 温湿度センサーを読む

**やりたいこと**: I2C の温湿度センサー AHT25 から、1 秒ごとに 5 回、温度と湿度を読んで出します。センサーとのやりとりは、配布物のドライバ `aht25.sn` が包んでいます。

```
`aht25.sn`@~

fail : e ? seq3 (print `error `) (println_int e) e
loop : i ?
	i >= 5 : 0
	(aht25_measure 0) < 0 : fail (aht25_measure 0)
	loop2 i (aht25_show 0)
loop2 : i w ? seq2 (aht_wait 1000) (loop (i + 1))
start : r ?
	r < 0 : fail r
	loop 0
start (aht25_init 0)
```

パソコンでの練習は、センサーの代わりに模擬の装置を繋ぎます(温度 23.5、湿度 61 を返す模擬)。このファイルは配布物の `aht25_demo.sn` です。

```
python3 sign_interp.py aht25_demo.sn --i2c=aht25:23.5,61
```

実行結果は次のとおりです(1 秒ごとに 5 行、最後に `0`)。

```
T=23.50 C RH=61.00 %
T=23.50 C RH=61.00 %
T=23.50 C RH=61.00 %
T=23.50 C RH=61.00 %
T=23.50 C RH=61.00 %
0
```

**ひとこと**: `aht25_init`、`aht25_measure`、`aht25_show` は `aht25.sn` の関数です【拡張】。小数は Sign に無いので、温度を 0.01 ℃ の整数(`2350`)で持ち、表示するときだけ `23.50` の形の文字列にしています【拡張】。失敗は負の数で返り、`fail` が表示します。実機でこのセンサーを読むことは、ここでは確かめていません。
