# 第18章 器の配置と特殊化

## 器を返すときの場所は、呼ぶ側が用意する

リストや構造体(器)を返す関数は、戻り値をレジスタ 1 つでは返せない。仕様の `stack_abi.md` §4.7 は、返す場所を「呼ぶ側が用意する」と定めている。x8 に返値スロットの先頭、x15 に容量を渡す組で、これを `sret` と呼ぶ。x8 の使い方は AAPCS64 と同じだが、Sign はもう 1 本(x15)を対にする。この組みは仕様が決めている。第15章の末尾呼び出しが戻り値の領域を持つ関数を対象にしないことと、この組みがどう関係するかは、この章では確かめていない。

実装は、返り値を置くスロットを関数ごとに静的に決めている(`emit_slot`)。ノートの「非ボックス化の実測」によると、サンプル 42 本で返値スロットは全部で 38 個あり、内訳は次のとおりである。

| 形 | 個数 |
| --- | --- |
| 平ら・定数 3 語 | 8 個(すべて `suika_flat.sn`) |
| 平ら・定数 8 語 | 26 個 |
| 入れ子・定数 | 4 個 |
| 実行時に決まる上界 | なし |

スロットの大きさはこのサンプルではすべて定数で決まった(実行時に決まる上界は 0 個)。

**試して、やめた案: 小さい戻り値をレジスタで返す。** ノートの見込みはこうだ。該当する 8 個は 1 本のプログラムに集中している。`suika_flat.sn` の命令 10733 のうち、スロット関連(`sub sp`・`mov x8`・個数・捨てる)は全スロット込みで 159(1.5%)。呼び規約(sret = x8)の変更が要るのに対して効果が小さいので、実装は見送る。実行時間は測っていない。

見送りの理由が「呼び規約を変えるという大きさ」と「見込める効果 1.5%」の天秤である点に注目してほしい。呼び規約は仕様と実機の両方に触れるので、変えると確かめる範囲が大きくなる。小さな得のためにそれを走らせないという選択である。

## 関数を渡す形は、呼び出しごとの実体に書き換える

`$` で渡した関数を `@p 引数` で呼ぶ形(高階関数)は、実行時に飛び先を決めない。`sign_inline.py` が、呼び出しの所ごとに渡された関数を埋め込んだ実体を作り、呼び出しをそちらへ付け替える。関数の番地を渡す引数は消える。

この章で実際に走らせて確かめた例を示す。プログラムは次の 4 行。

```
sq : x ? x * x
inc : x ? x + 1
ap : f x ? @f x
(ap $sq 3) + (ap $inc 3)
```

既定の読みで走らせると 13(9 + 4)。`--asm` で出したアセンブリにはラベル `sq`・`inc`・`_uap_24_sq`・`_uap_24_inc`・`_.main` が並び、`ap` 自身は出ない(第14章の使われない関数の除去)。間接呼び出しの `blr` は 0 回である。実体の名前はアセンブリではこの形になるが、`sign_inline.py` の説明文では `元の名前$渡した関数の名前` と説明している(名前の付け方は実装の詳細)。

**仕様どおりの部分と、この実装だけの部分を分ける。** `sign_inline.py` の説明文が自分で分けているので、それに従う。

| 区分 | 内容 |
| --- | --- |
| 仕様が定める | クロージャ・部分適用は「コンパイル時特殊化」(`stack_abi.md`)。前置 `@` は type\_system.md §4 |
| 設計者の実装に合わせた | 実体の名前の付け方、再帰する関数も実体にする、名前の無い関数を最上位へ持ち上げる、`@p` の引数の数が合わない形を名指しで断る |
| この実装だけの選択(利用者の裁定 2026-11-13) | 関数の仮引数を**別の**高階関数へ渡す形も実体を作る。残る仮引数が 0 になる形は実体を作らず、呼び出しの所へ本体を置く |

実体の数には上限(`MAX_INSTANCES = 256`)がある。上限を超えたときや特殊化できない形は `SpecError` で断る(ここでは「断る」の経路の存在を読んだだけで、どこから実際に断られるかは確かめていない)。

**インライン展開の基準は、設計者への問いとして残す点と分ける。** 特殊化は仕様が定める動きなので「仕様どおり」。一方、関数をどこまで呼び出し側へ埋め込む(インライン展開)かの基準は、今のところ仕様にあると確かめていない。この章では「設計者への問い」の候補として扱い、実装は決めない。

## 限界

- 返値スロットの数と「1.5%」は実装ノートの記録で、ここで再計測していません。サンプル 42 本のうち 8 個が 1 本に集中しているので、他のプログラムで同じ割合になるとは限りません。
- 特殊化の例は小さな 4 行で、速さは測っていません。間接呼び出しが無くなることと、実際に速くなることは別です。
- この章は構造体やリストの「平坦化」の仕組み自体を説明していません。ノートの一部(「平ら」「入れ子」の分類)を読んだだけです。
- メモリ配置(`#`/`##`/`###`)との関係は設計者回答待ち(D1・D4、第27章)です。

**仕様由来と実装の選択。** sret(x8 と x15)と特殊化は仕様が定めるものです。返値をレジスタで返す案を見送ること、仮引数を別の高階関数へ渡す形も特殊化すること、残り仮引数 0 の形で実体を作らないことは実装だけの選択です。
