# 第29章 試して残したもの、実装していないもの

## 作って、既定にはしなかった道: `--via-sir`

`python3 sign.py --asm --strict --via-sir` は、実装ノート(第二段階、2026-11-22)にある「旁路」である。`--strict` の読みを中間表現 SIR に下し、`raise_ast` で旧い構文木に戻してから機械語を出す。これに対して既定は、第13章の旧い経路(`strict_rewrite`)のままである。

ノートが記録している結果は次のとおり。

- 整数・整数リスト・部分適用の流れの乱数で、SIR 経由の一致は旧経路と同じかそれ以上、誤答 0。
- 文字列・器・範囲・展開(`~`)・節の値は SIR の外。ここは評価器と機械語を `test_asm_strict.py` が直接突き合わせる。
- 旧 AST の補正 6 つを `SIGN_NOPATCH` で切って測ったところ、切ると誤答になるのは補正 5(`!=`)だけ。

これを「既定にする」に踏み切らない理由は、ノートの記録から次の 3 点と読める。理由を明示した記録はないので、ここはこの章の解釈である。

1. 範囲が狭い。SIR が扱えない形は `Unsup` で断るので、既定にすると今通っている形が断りに変わる可能性がある。
2. 一致を言う道具に誤りがあった。`run_asm` の戻りの形を取り違えて、機械語の答えを全部「断り」と数え、「誤答 0」が何も示していなかった時期がある(第2章の限界に書いた)。新しい道を既定にする前に、突き合わせの道具をもう一度洗い直す価値がある。
3. 旧い道は誤答 0 で動いている。変える得が、変えるリスクを上回っていない。

判断は実装だけの選択であり、仕様は中間表現を置くかどうかを定めていない。新旧のどちらでも、観測(第3章)が同じなら仕様に反しない。

## まだしていないこと、確かめていないこと

実装していないものと、実装はしたが確かめていないものは違う。ノートの記録から、この 2 つを分けてしまう。

| 区分 | 項目 | 今の状態 |
| --- | --- | --- |
| 未実装 | `io@`(標準ライブラリの取り込み) | 取り込み宣言の行は木に出ないので読み飛ばし、取り込んだ名前は定義の無い名前と同じ読みにする(木の出力の範囲。実際に取り込む動きは無い)。spec\_track で誤読ではなく「未実装」と分けた範囲が 2 件 |
| 一部実装・未確認が残る | R133(括りの欄と仮引数の名前) | 同じ関数の仮引数どうしの同名は `--check --strict` が実行せず断る。仕様の見本と突き合わせていない側が残る(「枝で選ぶ括り」と並べて記録)。設計者への問い B1 とも絡む |
| 実機で未確認 | 画面表示、外部配線の GPIO、マウスやキー | 第26章で確かめた範囲の外 |

SPI ループバック(送った 4 バイトがそのまま返った)と AHT25(2417 = 24.17 ℃、`I2C_RDWR` が 2 メッセージで通った)は、実機で確認済みです。

「なぜ未実装なのか」は、今のところノートに仕様を理由として書いた記録を見つけていない。先送りの作業として残っていると読むのが自然だが、ここでは断定しない。

**実機で確かめていないということは、答えが違うということではない。** エミュレータや疑似カーネルでは一致していて、実機にしか無い要素(配線、本物の画面、実機のセンサ)で分からないというだけである。読者は、最適化を進める前にこの線を引いておくとよい。「一致した」と言える範囲がそれだけ狭いと、最適化で壊したときに気付けない範囲も狭い。

## 限界

- この章は実装ノートの記録を読んでまとめたもので、再実行していません。
- `--via-sir` を既定にしない理由は、ノートに直接の記述がなく、この章の解釈です。
- R133 の実装範囲は、ノートの一部の行(仮引数の同名、欄の関数を名前の鍵で引く括り)から読んだものです。網羅的な一覧ではありません。
- GitHub Actions での成功実行、`io@` や実機での未確認項目の進捗は、ここで確かめていません。

**仕様由来と実装の選択。** `--via-sir` を既定にするかは実装だけの選択です。`io@` や R133 は仕様に書かれたものの実装状況ですが、B1 のように仕様どうしが食い違う点は設計者の答えを待ちます(第27章)。実機で確かめていないという状態は、仕様の話ではなく確認の範囲の話です。
