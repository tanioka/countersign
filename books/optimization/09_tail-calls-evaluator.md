# 第9章 末尾呼び出しを評価器で

## 「呼ぶ代わりに TailCall を返す」

末尾再帰をスタックを使わずに回すのが、評価器の末尾呼び出しである。やり方は単純で、関数の本体を評価する `ev_tail` が、**末尾の位置では関数を呼ぶ代わりに `TailCall`(呼び先と実引数を入れた小さな箱)を返す**。呼び出し側の `run_fixed_` の輪がそれを受け取り、すぐ次の呼び出しを同じ輪の中で続ける。呼び出しの入れ子は作られない。

切り替えるスイッチがある(`SIGN_NO_TCO=1`)。このコンテナで、整数の速い道と第7章の速い道を両方切って(`SIGN_NO_PURE=1`、`SIGN_NO_FAST=1`)、次のプログラムを走らせた。

```
c : n a ?
	n < 1 : a
	c (n - 1) (a + 1)
c 300000 0
```

| 設定 | 結果 |
| --- | --- |
| 末尾呼び出しあり(既定の設定) | 300000(2.5 秒) |
| `SIGN_NO_TCO=1` | 「再帰が深すぎます(スタックの大きさが足りません)」 |

末尾呼び出しがないと 30 万段の再帰で評価器のスタックが足りなくなる。あると、同じプログラムが答えを返す。この章の主題は速さではなく、「深さに限りがない」ことである。

上の表の時間はこのコンテナでの値で、他の道(第7章・整数の輪)を切った条件でのものである。既定の道だと同じプログラムは約 0.5 秒で終わる。

## 末尾の位置と、末尾でない位置

`ev_tail` のコメントは末尾の位置を「cases の選ばれた行の値・括り・並び」としている。表にすると次のとおり。「根拠」はコードと実装ノートの記述である。

| 位置 | 末尾か | 根拠 |
| --- | --- | --- |
| 分岐(cases)の既定の行と最後の枝の値 | 末尾 | `ev_tail` のコメント「既定の行と最後の枝の値は末尾」 |
| 最後でない枝の値(`c & v \| 次の行` の `v`) | **末尾でない** | 実装ノート R128・R129(これは仕様の記述) |
| 括り・並び | 末尾(並びは限りがある) | 先頭が仮引数を持つ関数で、値の実引数がちょうど口の数のときだけ |

最後でない枝の値を末尾にしないのは、仕様(R128・R129)が「ここは末尾ではない」と定めているからである。「値が空なら消えて次の行へ進む」規則との関係が考えられる(呼び出しが返ってくるまで空かどうか分からない)が、これは私の推測である。仕様が理由を書いているわけではない。

この結果、最後でない枝の値の位置での再帰は、深さの分だけスタックを使う(実装ノートも「深さの分だけスタックを使う」と明記している)。最初の実装ではここも末尾にしていたが、仕様(R128)に合わせて直したという経緯である。

このほか、2 つの形を末尾として扱うが、動くモードが違う。

- **逆適用 `x f` の末尾**: 既定の道だけ(`--strict` では使わない)。コードのコメントに「10 万段でも溢れない」とある。
- **`,` の鎖の最後の呼び出し**: `--strict` だけ。`,` の鎖に前の関数が 2 つ以上あるとき、最後の呼び出しを末尾とする(value\_spec V10)。

## 深さの限界: どこで止まるか

末尾でない位置の再帰は、深くなれば止まる。止まり方は経路とモードで違う。

| 経路 | 止まり方 | どこから決まるか |
| --- | --- | --- |
| 評価器(既定) | 「再帰が深すぎます(スタックの大きさが足りません)」で終わる | 起動時にスタックを 512MB から試して確保し、再帰の上限をそれに合わせる(最大 20 万) |
| 評価器(`--strict`) | その呼び出しは `_` と information `resource-depth` | 上限は再帰の上限から計算(実装ノートは約 6200 段)。末尾呼び出しは数えない |
| 実機(機械語) | OS のスタックを使い切りシグナルで終わる(rc 139) | 仕様に無い終わり方(第5章) |

これを観測の違いとして扱う。`--strict` の評価器が「空(`_`)」を値にして続けるのと、機械語がシグナルで落ちるのとでは、終わり方が違う。既定の評価器もエラーで終わるので、機械語とはこれも終わり方の違いである。上限の段数は仕様に書かれておらず(実装ノートも「値は実装の都合」としている)、どれも仕様の答えではない。仕様(V10)が定めるのは「入れ子の深さが上限に届いたら `_` と information `resource-depth`」という形だけである。

末尾呼び出しの場合はどの経路でも深さを使わない。機械語側の末尾は第15章で述べた。

## 仕様から決まること、実装だけの選択、限界

| 分類 | 内容 |
| --- | --- |
| 仕様から決まる | 最後でない枝の値は末尾でない(R128・R129)。`,` の鎖の最後の呼び出しは末尾(V10)。入れ子が上限に届いたら `_` と `resource-depth`(V10) |
| 実装だけの選択 | TailCall と輪という仕組み。深さの上限の段数(約 6200)。既定で再帰が深すぎるときのエラー。逆適用の末尾を既定だけにしたこと |
| 経路の違い(未解決ではない、実装の限界) | 深い非末尾再帰での終わり方。評価器と実機で異なる |

限界は三つ。

- 末尾呼び出しは「呼び先がユーザ関数で、実引数の数が口の数にちょうど合う」場合だけ。部分適用などは普通の呼び出しになる。
- 30 万段を超える深さを試していない。
- この章の測定は 1 種類のプログラムだけで、末尾呼び出しが他の形(並び・条件の入れ子)でも同じ効果を出すことは確かめていない。
