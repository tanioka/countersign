# 第4章 何を測るか

## 測るものを増やす

最適化の「速くなった」を示すには、どこを測るかを先に決める。このプロジェクトで実際に測っているものを、測り方と一緒に並べる。

| 測るもの | 測り方 | 使い道 |
| --- | --- | --- |
| 命令行数・コードサイズ | 出力のアセンブリの行数 | ピープホール・共通部分式などの前後(第17・19章)。実際の速さではない |
| 走行時間(壁時計) | 実機で周回(既定 5 周)して測る | 直列と並列の倍率(第21章) |
| 周回ごとの CPU 時間 | `RUSAGE_CHILDREN` の差(user + sys) | 空回りかコアを使い切れていないかを見分ける |
| 文脈切り替え | 自発・強制の回数 | 待ち・起こしの多さ |
| スレッドごとの CPU 時間 | `/proc/<pid>/task/*/schedstat` の先頭欄(ナノ秒)を走行中に読む | 仕事の分け方の偏りを見る |
| ARM クロック・制限 | `vcgencmd` | 発熱や電圧で遅くなっていないか |

最後の 3 つは、「周回の壁時計」だけでは原因が分からなかったときに順に足したものである(実装ノート第109段続き 15〜28)。次の節でその経緯を読む。測るものをあらかじめ全部用意するのではなく、「説明できない結果」が出たときに足すという順で、測る手間を増やしている。

## fib4 の遅い周を追う

実機(Pi 4)で `fib4` を `--par=4` で 5 周すると、速い周は壁時計 0.54 秒前後、遅い周は 0.91 秒前後と、二つの山が出た。答えはどちらも同じだった。実装ノートに残る仮説と検証の順を、そのまま並べる。

| 順 | 仮説 | 検証 | 結果 |
| --- | --- | --- | --- |
| 続き 16 | 遅い周は CPU 時間がほとんど増えない(速い周 2.13 秒に対し 2.21〜2.22 秒)ので、**同時に動けるコアが減った**のだろう | 4 本のほかに 3 本の `_p3` を足し、`_p3` に山が出るか(続き 17・18) | `_p3` は山が出ない。しかし 3 本目がほとんど効かず、仮説の決め手にならない |
| 続き 19 | 軽さ判定が「永久に無効化」され、分け直しが止まる | 軽さの境を変えた版(続き 20) | 半分だけ支持。境を変えるだけでは直らず、極小の仕事まで出す版は切り替えが急増して CPU も増える |
| 続き 21〜25 | 切り替えの嵐(futex の起こしと待ち)が原因 | 回数の計測、`--par-spin` の見回り | **外れ**。見回りは切り替えを減らすが壁時計は良くならない |
| 続き 27〜28 | スレッドごとの CPU 時間を見れば分け方が見えるはず | `schedstat` を 5 ms ごとに読む | 原因が分かった |

**分かったこと**(続き 28)。

- `_p4` の遅い周は、4 本の CPU 時間が 552 / 550 / 900〜919 / 203 ms と偏っていた。1 本が 900 ms(全体の約 41%)で、1 本は 203 ms で終わって何もしていない。壁時計 0.91 秒は最も長い 1 本の時間である。合計の CPU 時間は速い周と同じ約 2.2 秒だった。
- 続き 16 の仮説(同時に動けるコアが減った)は**外れた**。コアは空いていて、**仕事の分け方が粗く偏っていた**のが実際の原因だった。
- 「軽さを永久に無効化」するのが原因という続き 19 の推定は正しかったと、続き 28 で結論を直している。続き 20 で「半分だけ支持」とした理由は、軽さを 0 にした版は別の損(極小の仕事の手間で CPU が 2.2 秒から 3.3 秒へ約 1.5 倍)で同じくらい遅くなっていたからだった。

この結果が第23章の `--par-relight`(軽さを積みの深さで覚える)につながる。

**仮説が外れること自体が測定の価値。** 同時に動けるコアが減ったという最初の見立ては、CPU 時間と壁時計の比という 1 つの指標から見れば筋が通っていた。スレッドごとの CPU 時間という別の指標を足して、初めて偏りに気づけた。

## 限界

- 診断自体が結果を変えうる。続き 28 の記録に、「5 ms ごとの読みの影響で、この診断の下では fib4 `_p4` の速い周が出なかった(8/8 遅い)」とある。
- スレッドごとの CPU 時間の読みは終了直前までの最後の読みで、誤差は 5〜10 ms 程度(記録)。
- 周回数は 5 周のときが多く、「山の頻度」は断定できないと記録されている(続き 19)。
- この章の数字は実装ノートの記録を読んだもので、Pi で再実行していない。

**仕様由来と実装の選択。** 測るものと測り方はすべて実装だけの選択であり、仕様は速さについて何も定めていない(観測の組には時間が入っていない。第3章)。どれだけ速くなったかは、答えが同じかとは別の測定の問題である。
