# 第25章 一致しないときの分類

## 四つに分ける

第24章のように三つの経路を突き合わせると、観測の組(終わり方・値・メモリ・警告)がすべて同じになるとは限らない。そこで「一致しない」を一つの箱に入れず、次の四つに分けて数える。定義は `fuzz_obs.py` の分類のコードからとった。

| 分類 | 意味 | どう扱う |
| --- | --- | --- |
| 誤答 | 両方が答えを出して、それが食い違う | バグ。終了コード 1 で失敗させる |
| 断り | 変換器が「この形は扱わない」と名指しで拒む(`AsmError`、`StrictRefusal`、評価器の断り) | 誤答ではない。比べないで別に数える |
| 罠 | 機械語が止まる(罠)。原因を x16 に印する(1 = 整数の溢れなど、3 = 部分適用の安全装置) | 安全装置(3)は「答えを出さず止める」選択なので誤答ではない |
| 未決 | 仕様が何も書いていない所で、経路が違う振る舞いをする | 誤答にも「許容」にもしない。別項目で数え、設計者への問いに渡す |

未決に入っているのは、このプロジェクトでは次の二つである。

- **A3(整数の溢れ)**: 評価器は結果を `!_` として知らせを出し、機械語は罠で止まる。
- **H1(書かれていない番地の読み出し)**: 評価器は `__`、機械語は 0 を返す。

どちらも「どっちが正しいか」を仕様が決めていないので、実装の側で片方を正解として直しはしていない(設計者回答待ち。第28章)。

## なぜ「許容」にまとめないか

食い違いを「これは仕方がない」と一つにまとめると、どこかで誤答がその中に紛れる。分ける理由は三つある。

1. **誤答をゼロに保てる。** 答えが食い違うのはバグだという線を崩さない。数え方を緩めて「誤答 0」にしたのではない。分類の境界をコードに書いている。
2. **断りと罠は、守るための失敗である。** 答えを誤るより、断る・止める方が安全である(何を断るかは名指しで記録する)。部分適用の安全装置(x16=3)は、答えを出さずに止めることを選んでいるので、誤答とも「許容」とも別の行にする。
3. **未決は、設計者の答えで中身が変わる。** どちらかを「正しい」と決めて直すと、設計者が逆を答えたときに観測が壊れる。特に「速い方を選ぶ」と最適化との相性が悪い(第28章で扱う)。

分類は一方向の決めではなく、「この組はどの箱に入るか」をコードで決めることで、毎回の実行で同じ基準で数えられるようにするのが目的である。

## 実測の内訳

**未決の具体例(H1)。** このコンテナで `fuzz_obs.py` の観測関数を直接呼んで確かめた。

| プログラム | 評価器 | 機械語 |
| --- | --- | --- |
| `0x500000 # 5` のあと `@0x500008`(書いていない番地を読む) | 空(`__`) | 0 |
| `0x500008 # 0` のあと `@0x500008`(先に書く) | 0 | 0 |

上の行だけが食い違う。このプログラムに「先に全部の番地へ 0 を書く」行を足して比べ直すと一致するので、`fuzz_obs.py` はその場合を「誤答」ではなく「未決」と数える。

**件数。** 乱数プログラムでこのコンテナにて再実行した(コマンドはどれも種 1)。

- `fuzz_obs.py 150 1`(評価器と機械語のメモリを書く形): 一致 43、未決(H1) 107、誤答 0、終了コード 0。
- `fuzz_obs.py 100 1 --three`(第24章の再実行): 値・リスト・流れの順で、機械語一致 83/94/62、断り 12/6/18、A3 未決 5/−/3、部分適用の安全装置の罠 17(流れのみ)。SIR は 3 つとも 100/100 一致。終了コード 0(誤答なし)。

読むときの注意を三つ。

- 「未決 107」は、乱数の作り方が書かれていない番地をよく読む形にしているから多い。実際のプログラムでどれだけ起きるかを示す数字ではない。
- 件数は 100と150 と小さい。第24章のノートにある型ごと 900 件の「誤答 0」は記録として引くにとどめ、ここでは再実行していない。
- A3 の「未決」は、その相手を「誤答」と言い切っていないだけで、機械語の罠が正しいと言っているわけでもない。

## 仕様由来と実装の選択、限界

**仕様由来。** 「答えが食い違うのはこわれている」という線と、「仕様が書いていない所はどちらが正解とも言えない」という筋道。A3 と H1 が未決なのは、仕様が何も書いていないからである。

**実装の選択。** 四つの名前と境界、安全装置(x16=3)を誤答に数えないこと、「先に 0 を書いて比べ直すと一致するなら未決」という数え方は、このプロジェクトの試験が決めたもので、仕様には書かれていない。

**限界。**

- 分類は乱数の作り方に依存する。作らない形はこの比べの外。
- 「未決」の中に本当の誤答が隠れていないとは言い切れない(先に 0 を書いて一致する場合だけを未決としているので、それを超える保証は無い)。
- 設計者の回答が出たら、未決の箱は「一致」か「誤答」に振り直す。第28章でこの系統の「最適化しない」理由を見る。
