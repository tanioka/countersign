# 第8章 副作用の判定

## 番地の集合で追う

最適化が「順序を入れ替えてよい」「答えを記憶してよい」と言えるのは、その式が外の世界とやりとりしないと言えるときだけである。Sign では外の世界とのやりとりは、`#`(書く)と `@`(読む)のどちらかに必ずなる。`sign_plan.py` はこれを、式ごとに「読む番地の集合 r、書く番地の集合 w」という組(`Eff`)で表す。

- r も w も空なら**純粋**。w が空でなければ「書く」、空でないのが r だけなら「読む」。
- 子の式の組は和集合で束ねる。呼んだ関数の組も同じように合わせる。関数の組は、呼び出しを通して「不動点」で求める。相互再帰でも、組がこれ以上変わらなくなるまで繰り返す。
- 2 つの式が「ぶつかる」のは、書く同士・書いてから読む・読んでから書くのどれかに同じ番地が入るとき。読む同士はぶつからない。

「同じ番地か」をどう言うかがこの章の中心である。次の節で見る。

## 迷ったらぶつかるとみなす

規則は安全側に倒してある(ツールの説明と実装ノートの記述)。

| 番地の形 | 扱い | 試験(`test_plan.py`)の結果 |
| --- | --- | --- |
| 定数で決まる(名前つき定数、`+ - *` の計算) | 別の番地と言える | `A` と `A + 4` への書き込みは同時にできる |
| 同じ定数番地 | ぶつかる(理由に番地を出す) | `A # …` を 2 つ並べると順番、「どちらも番地 0x500 を使う」 |
| 引数など計算で決まる番地(`*`) | どの番地とも重なりうる | `p # …` と `(p + 4) # …` でも順番 |
| 0x9000000 以上(デバイス) | 読み書きとも「書き込み」。入出力の順に意味がある | UART への書き込み 2 つは順番 |
| 引数として渡された関数を呼ぶ | 何をするか分からないので、読むも書くも「どの番地も」 | 「引数で渡された関数を呼ぶ関数は、副作用ありとして順番」 |

「迷ったらぶつかる」の理由は、**並列にしないという間違いは遅くなるだけで、並列にする間違いは答えが変わる**からである。誤判定のコストが非対称なので、傾きを安全側に置く。

実装の記述(ツールの先頭)によると、変えることを許すのは「引数は元々すべて評価される」という Sign の意味による。変わりうるのは「エラーが複数あるときどれが先に報告されるか」だけである。

## 実際に走らせて確かめる

`test_plan.py` の試験プログラムの関数をそのまま `sign_plan.py` にかけた結果の表である(このコンテナで実行)。

| 関数 | 判定 | 読む番地 | 書く番地 |
| --- | --- | --- | --- |
| `pure` | 純粋 | − | − |
| `rd` | 読む | 0x500 | − |
| `wr` | 書く | − | 0x500 |
| `uart` | 書く | − | デバイス 0x9000000 |
| `whoknows`(`p # 1`) | 書く | − | 計算で決まる |
| `rd2`(`rd` を呼ぶ) | 読む | 0x500 | − |
| `wr2`(`wr` を呼ぶ) | 書く | − | 0x500 |
| `mut1` と `mut2`(相互再帰) | 書く | − | 0x500 |

`rd2` が「読む」になるのは呼び出しを通して伝わるからで、`mut1` は自分では `#` を書いていないのに、相互再帰の相手が書くので「書く」になる。試験は 26 件すべて通った(このコンテナで再実行。`ok` 行 26)。ディレクトリの `*.sn` をすべて解析して落ちない確認も含む。

## 仕様由来、実装の選択、限界

**仕様由来。** Sign は引数をすべて先に左から右へ評価し、引数どうしは互いの値を使わない(`sign_plan.py` の先頭の記述)。この意味が、副作用がぶつからない限り引数どうしを同時に評価してよいという根拠になる。

**実装の選択。** 番地を「読む集合・書く集合」で表す作り、計算で決まる番地を「どことも重なりうる」とすること、デバイスの読みを書き込み扱いにすること、引数で渡された関数を「何でもあり」とすることは、すべて実装の選択である。

**第10章・第21章との関係(正確に)。** この章のツール `sign_plan.py` は計画を出すだけで、実際には並列に走らせない。記憶(`_pure_memo`)と `--par` の判定はこのツールとコードを共有していない(`sign_plan` を import しているのは試験だけ)。記憶は各関数のソースにメモリを読み書きする部品の名(`_psrd`、`_pswr`、`_pswc` 系)があるかを見て、それを呼ぶ関数も除く。`--par` は「純粋 = 速い道の計画があり、計画のどこにもメモリを読み書きする部品が無い」を基準にしている(実装ノート)。つまり「メモリに触れない」という同じ考え方の別々の実装であり、共通の判定関数ではない。目次の以前の「共通の土台」という言い方は実際と合わなかったので直した。

**限界。**

- 重さ(構文木の節の数)は静的な概算で、実際の時間ではない(ツールの説明)。
- 「迷ったらぶつかる」のため、実際にはぶつからない組も順番を守ることがある(同時にできたはずの組を逆に逃す。答えは変わらない)。これは速度の取り逃しであり、答えの間違いではない。
- 3 つの判定が食い違うかを直接に比べる試験はここでは確かめていない。
