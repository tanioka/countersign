# 第26章 実機で確かめる

## なぜ実機で確かめるか

エミュレータ(コンテナ側の疑似カーネル `fake_kernel.py`)の上で一致していても、実機で同じとは限らない。疑似カーネルは「実機はこう振る舞うはず」という見込みで作っている(`pi_check/README.md` の記述)。見込みが外れる場所を見つけるのが実機の役割である。

手順は次のとおり。

1. コンテナで `build.py` を走らせ(clang と ld.lld が要る)、AArch64 の静的 ELF を `bin/` に作る。`make_expected.py` で疑似カーネルの予想 `expected.json` を作る。
2. Pi(64 ビットの Raspberry Pi OS)に `pi_check/` を丸ごと置き、`python3 run_on_pi.py` を走らせる。`report.md`・`report.json`・`trace/`(strace)ができる。
3. それをコンテナへ戻して、予想と突き合わせる。

判定は「一致・許容・参考・食い違い」に分ける。許容と参考は、人や外の配線で答えが変わるもの(例: SPI のループバック、キーを押す入力)を、食い違いと混ぜないための箱である。判定の基準自体も、疑似カーネルの予想と「実機の振る舞いの見込み」から決めたと README にある。

ここで示す数字は、リポジトリの `pi_results/` と `pi_check/` に残っている記録ファイルから読んだものである。このセッションでは Pi につなぐことをしていないので、この章の数字はすべて「記録を読んだ」もので、再実行したものではない。

## これまでの結果

`pi_results/` と `pi_check/` の記録ファイルにある件数を、段階ごとに並べる。誤答はどの段階でも 0 である。

| 段階・記録 | 件数 | 内訳 |
| --- | --- | --- |
| 第三段 初回(`stage3_compare.txt`) | 69 | 一致 64、異常終了 5(整数 29・呼出し 13・メモリ 16・末尾再帰 11) |
| 第三段 再走行(`stage3b`、`stage3c`) | 69 | 一致 67、異常終了 2(末尾再帰 11 件は全部一致) |
| 第四段(`stage4_compare.txt`) | 44 | 一致 44(UART 4・時計 2・メモリ 4・ファイル 2・ネット 6・DB 2・並列 24) |
| さらに乱数(`compare_seed1.txt`) | 301 | 一致 272、断り・罠(許容) 26、strict が断る 3、間違った答え 0 |
| `pi_check` 初回(`pi_check_pi4`) | 123 | 一致 113、参考 9、許容 1 |
| `pi_check` 再測定(`pi_check_pi4_relight`) | 145 | 一致 131、参考 13、許容 1 |

数字の読み方を三つ。

- **異常終了 2 件**は、深い非末尾再帰(100 万・1 億回)で OS のスタックが尽き、終了コード 139 になるものである(実装ノートは「仕様外」としている)。初回で異常終了だった末尾再帰の 3 件は、再走行で一致になっている(実装ノートでは末尾再帰 11 件が全部一致、相互再帰の 1 億回も一定のスタック)。この間に入れた変更を記録ファイルだけから特定してはいない。
- `stage3c` は観測の組の「警告」も数えていて、「溢れの知らせを評価器は出し、実機は出さない」が 10 件ある。これは第25章の A3(未決)であり、誤答ではない。
- `pi_check` の「参考」「許容」は、つなぐ物や人の操作で答えが変わるものである(例: `t_spi_rx` の受信が 0 なのはループバックの線をつないでいないからで、つないだ実行では 4027538085 が返った)。

実機は Raspberry Pi 4 Model B(Linux 6.18.60+rpt-rpi-v8)で、第21章の並列の計測もこの一式の上にある。

## まだ確かめていない点、限界

「誤答 0」をどこまで信じてよいかを、確かめた範囲と、確かめていない範囲に分けて記す。

**確かめていない点**(このプロジェクトの記録にあるもの)。

- tty コンソールでの画面表示(`t_gfx_fb` は「参考」で、呼び出しが通ることは見たが、画面に出るかは目で見る必要がある)。
- 外部配線の GPIO、マウス・キーの入力(`t_input_live` は人が押す・動かす必要があり、参考扱い)。
- Raspberry Pi 4 以外。第21章・第23章で見たとおり、Pi 3 A+ の計測記録もあるが、ここで示した表は Pi 4 のものである。

SPI ループバックと AHT25 は、実機で確かめ済みです。SPI は構造体 32 バイトが受理されて戻りが 4、MOSI と MISO をつないだループバックで送った 4 バイトがそのまま返りました。AHT25 は `t_i2c_aht25` が 2417(24.17 ℃)、`t_i2c_probe` が 0 で、strace では `I2C_RDWR` が 2 を返して 2 つのメッセージが通っています。

**限界。**

- 誤答 0 は「試した件数の中で 0」であり、試していない形については何も言えない。
- 異常終了(スタック枯渇、終了コード 139)は誤答ではないが、「答えが出ない」ことは変わらない。実機で罠は無限ループ(終了コード 124、第5章)になる点も変わらない。
- この章の数字は記録を読んだもので、このセッションで再実行していない。

**仕様由来と実装の選択。** 実機で確かめる手順や、「一致・許容・参考」の判定基準はこのプロジェクトの選択である。仕様が出力を定めている範囲でこそ、「一致」の意味が仕様由来と言える。
