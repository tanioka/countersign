# 第17章 ピープホール最適化

出力した命令列を関数ごとに読み直して縮める後段は、「判らなければ何もしない」という安全の決まりを乱数の命令列で鉄えたところに強さがある。

## なぜ後段で縮めるか

Sign のコンパイラは式を木のまま素直に命令にする。そのため「変数を読んで、一時レジスタに移し、定数を別のレジスタに置いて、引く」といった、同じ値の置き直しや使い捨ての即値レジスタが多い。例えば再帰の `fib` では、実引数の `n - 1` を計算するだけで複数の `mov` が出る。

これをコンパイラ本体で考えて作ると、生成が複雑になる。そこで「素直に作ってから、出力した命令列(文字)を関数ごとに読み直して縮める」後段を足した(`sign_peep.py`)。意味は変えない。Sign の仕様とは関係のない、処理系の中だけの最適化である。既定で有効で、`--no-peephole`(または環境変数 `SIGN_PEEP=0`)で切れる。切れることは、最適化を疑うときに「あり」と「なし」を比べられるという意味でも大切になる。

## 四つの書き換え

| 名前 | やること | 条件 |
| --- | --- | --- |
| P1 保存→読み込みの転送 | `str xS,[x29,#k]` と `ldr xD,[x29,#k]` の読みを消すか `mov` にする | 間に別の書き込み・呼び出し・ラベルが無いときだけ |
| P2 即値の畳み込み | `mov xA,#n` を `add/sub/cmp` などの最後のオペランド `#n`(0〜4095)として埋め、`mov` を消す | xA がそのあと読まれない |
| P3 コピーの伝播 | `mov xA,xB` のあとの xA の読みを xB にする | xA が死んでいれば `mov` も消す |
| P4 定義の付け替え | `… xA を作る … mov xB,xA` を、最初から xB に作る | `subs x9,x0,#1` のような、xB を読んで xA を作る命令も可 |

ほかに、自分への `mov`、次の行へ飛ぶだけの `b` の削除と、`b.cc A / b B / A:` の反転もする。どれも「このあとそのレジスタが読まれるか」を調べてから出す。この調べ方が次の節の安全の決まりになる。

## 安全の決まり

判らなければ何もしない。そのための約束が五つある。

1. **読まれるかの調べ方**: 同じ関数の中のラベルへの分岐は両方の道を辿り、**全部の道で** 読まれる前に書かれる、罠に落ちる、`ret` に到ると言えるときだけ「死んでいる」とする。
2. **罠への分岐**: 罠(`.Ltrap*`)への分岐は何も読まないと見る。
3. **呼び出し**: Sign の関数への `bl` は x9〜x12 を壊す側、x0〜x7 を引数として読むとみなす。`_sign_*` の補助、`blr`、`br`、未知の命令・指令・書き戻し付きの番地、w の形、`movk` は「全部読まれる」とみなし、ここで探索を止める。
4. **触るレジスタ**: x0〜x12 だけ。x13(`__` の印)、x15・x17(返値の受け渡し)、x29・x30 は触らない。
5. **並べ替えない・保存を消さない**: 命令を入れ替えたり、`str` を消したりしない(死んだ保存の除去はしていない)。

罠への分岐を「何も読まない」と見るのは、罠で止まったときに観測されるのが終わり方と原因だけで、x0〜x12 の値ではないという前提に基づく。この前提を確かめるのが乱数の命令列の試験(次の節)で、罠に落ちたかどうかを比べる項目に入っている。

## バグと試験、効果と限界

初版の P2 にバグがあった。`mov x0,#1` とそれを使う命令の間に条件分岐があるとき、分岐先でその値が読まれるのを見ずに `mov` を消した(使う命令より後ろだけを見ていた)。見つけたのは乱数試験で、消す判断を「`mov` の位置から、分岐も含めて」やり直す形に直した。

試験(`test_peep.py`)は三つの種類で、縮む形と、縮んではいけない形(あとで読まれる・分岐先で読まれる・w の形・`_sign_` の補助の前)が残ること、乱数の命令列 3000 本を小さな実行器で最適化の前後に走らせて、終わりの x0〜x8、フレームの内容、罠に落ちたかが一致すること、`fib_bench` の命令が減ることである。全体の答えは `test_asm` などが、既定で最適化を通した出力で確かめる。

効果は命令の行数で測る。この章を書く際に `test_peep.py` を走らせた結果は、`fib_bench` が 82 行から 66 行、乱数の命令列全体で 44942 行から 41773 行(約 7% 減)である。実装ノートには以前の版の数字(84 → 70 行)があるが、これは後の変更で動いている。**実機の速さは未測定**で、命令数が減ったことと速くなったことは区別する。

まだやっていないことは、死んだ保存(`str x0,[実引数]` のあとで読まれないもの)の除去、ラベルをまたぐ値の転送、命令の並べ替え、`.Ltrap` を共有する `b.vs` の統合、`--par` の実行環境(手書きの部分)への適用である。
