# 付録A 用語集

## 観測・経路・一致の分類

| 用語 | 意味 | 章 |
| --- | --- | --- |
| 観測 | (終わり方, 値, メモリ, 警告)の組。最適化が変えてはいけないもの。終わり方は値・空・罠・流れ・断り | 3 |
| 厳密評価(`--strict`) | 仕様の読みで式を評価する評価器の走り方 | 2 |
| SIR | `sign_sir.py` の正規化された中間表現。下せない形は理由つきで断る | 2・11 |
| 機械語(`--asm`) | AArch64 のアセンブリを出してエミュレータや実機で走らせる道 | 2 |
| 誤答 | 両方が答えを出して食い違うこと | 2・25 |
| 断り | 片方が「出せません」と断ること。誤答ではない | 2・25 |
| 罠 | 機械語が止まること。実機では wfi のループが打ち切られて終了コード 124 | 5・25 |
| 未決 | 仕様が何も書いていない点で道により振る舞いが分かれること(A3、H1) | 25・28 |
| A3 | 整数の溢れ(x16=1)。評価器は `!_` と知らせ、機械語は罠 | 16・27 |
| H1 | 書かれていない番地の読み。評価器は `__`、機械語は 0 | 25・28 |
| 設計者への問い | 仕様文書どうしの食い違い 6 件(A3・A5・B1・C4・D1・D4)を実装せずに残したもの | 27 |

## 最適化・並列・測定

| 用語 | 意味 | 章 |
| --- | --- | --- |
| 速い道(`run_pure`) | 整数だけの純粋な関数を、木の走査をやめて翻訳して走らせる道 | 7 |
| 純粋関数 | メモリに触れない関数。番地の集合を読む・書くに分けて追う(迷ったら「ぶつかる」と見る) | 8・20 |
| 末尾呼び出し | 呼ぶ代わりに次の呼び出しを返し、スタックを使わずに回すこと。機械語では `b callee` | 9・15 |
| 記憶(`_pure_memo`) | 純粋関数の答えを覆えること。観測を変えない処理系だけの選択 | 10 |
| 書き換え(左辺と右辺) | 観測が等しい左右の組で証明する局所的な変換 | 12 |
| 罠になりうる命令 | 溢れ検査など。動かしたり消したりしない | 16・17 |
| ピープホール | 出した命令列を関数ごとに読み直して縮める最適化。判らなければ何もしない | 17 |
| sret | 器を返すとき、返す場所を呼ぶ側が用意する組み。x8 が先頭、x15 が容量 | 18 |
| 特殊化 | `$` で渡した関数を呼ぶ形を、渡された関数ごとの実体に書き換えること | 18 |
| 投機実行(`--par-spec`) | 選ばれないかもしれない仕事を先に走らせ、不要なら捨てる | 22 |
| 巡り戻し | 投機で溢れの罠が起きたとき、親が直列で計算し直すこと | 22 |
| 軽い仕事 | 極小で、出す手間が得を上回る仕事。`--par-relight` は積みの深さで軽さを覚える | 23 |
| 山 | 周回ごとの時間が二つに割れること。測定ツールでは最大が最短の 1.3 倍を超えたとき「山あり」 | 4・21 |
| スレッドごとの CPU 時間 | `/proc/<pid>/task/*/schedstat` で読む。分け方の偏りの診断に使う | 4 |
| 三者一致テスト | 評価器・SIR・機械語の観測を突き合わせる乱数テスト | 24 |

## 限界

- 用語の意味は、各章の本文で述べた範囲の要約です。この付録でことさらに調べ直したものではありません。詳しい条件や例外は章の本文を先に見てください。
- 「罠」の実機での見え方(終了コード 124)や「山」の 1.3 倍は、このプロジェクトの測定ツールの基準であり、一般の用語ではありません。
- 用語集には語の選択をしています。宣言やツール名のすべてを網羅したものではありません。

**仕様由来と実装の選択。** 「観測」「未決」の語は仕様と実装の境を語るためのこの本の言葉です。仕様が定めた用語ではありません。記憶・特殊化・投機実行などの最適化は実装だけの選択です(特殊化の「コンパイル時特殊化」という考え自体は仕様の記述、第18章)。
