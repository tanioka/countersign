# 付録C テストの使い方

## 手元で走らせるもの

リポジトリ(`countersign`)のルートで、次のように走らせる。表の「今回」の列はこの付録を書く際に実際に走らせた結果で、空欄は走らせていない。

| コマンド | 何を確かめるか | 今回 |
| --- | --- | --- |
| `python3 fuzz_obs.py [件数] [種]` | メモリを含む観測を、strict の評価器と機械語(エミュレータ)で乱数で比べる。誤答があれば終了コード 1 | `100 1`: 一致 27、未決 73(H1) |
| `python3 fuzz_obs.py --three [件数] [種]` | 評価器・SIR・機械語の三者を突き合わせる(第24章) | `100 1`: SIR 一致 100、機械語一致 83・断り 12・未決 5 |
| `python3 fuzz_sir.py [件数] [種] [--asm] [--lists] [--flows]` | 整数の式・関数について、strict と SIR(と機械語)を照合する | 走らせていない |
| `python3 spec_track.py [仕様リポジトリ] [--save] [-v]` | 仕様の見本(R 規則・V 規則)を取り込み、`--strict` の結果と突き合わせて規則ごとに数える | HEAD 0114ac8a: 一致 419、未切り分けの食い違い 0、既知の食い違い 10、省略 167(見本 596) |
| `python3 test_plan.py` | `sign_plan.py` の判定を確かめる | 「全部通った」 |
| `test_sir.py` | pytest 形式。SIR の既定の照合をまとめて回す(内部で `diff_observe.py` と `fuzz_sir.py` を呼ぶ) | 走らせていない |
| `python3 test_laws.py [-v] [法則 ID]` | 法則の地図と仕様の見本を `sign_interp.py` に当てる | 走らせていない |

見るところは、誤答が 0 かどうかだけではない。「断り」「未決」「既知の食い違い」がどの理由で数えられているかを読む。`spec_track.py` は、このプロジェクトでは「食い違いを理由つきの「既知」にして残す」道具でもある(第27章)。

## 実機(Raspberry Pi)で走らせるもの

実機では、この箱の側で「作って、期待値を用意し、Pi で走らせて、突き合わせる」の 3 段になる。段階のスクリプトと `pi_check/` がある。

| スクリプト | 何をするか |
| --- | --- |
| `pi_stage3.py make DIR` / `compare DIR` | 整数溢れ・関数呼び出し・メモリ境界・末尾再帰の最小プログラム。期待値は整数は Python の厳密計算、それ以外は strict 評価器の答え |
| `pi_stage4.py make DIR` / `compare DIR` | 装置(`--real-dev`)と並列(`--par`)。外に何もつながなくても確かめられるものだけ。並列は直列の機械語と処理系の答えに合わせ、時間も記録する |
| `pi_check/`(`build.py`→`make_expected.py`→Pi で `run_on_pi.py`) | 実機の食い違い洗い出し。`report.md` と `report.json` ができる |

`pi_check/` の手順は、README によると次のとおり。

1. この箱で `python3 build.py`(clang と ld.lld が要る)。`bin/` に AArch64 の静的 ELF ができる。
2. この箱で `python3 make_expected.py`。`expected.json`(疑似カーネルの予想)ができる。
3. Pi(64 ビットの Raspberry Pi OS)に `pi_check/` を丸ごと置き、`python3 run_on_pi.py`。
4. I2C・SPI を raspi-config で有効にし、ユーザーを `gpio`・`i2c`・`spi` グループに入れる。GPIO26(37 番ピン)には何もつながない。
5. SPI のループバックを見るなら、GPIO10 と GPIO9 を線 1 本でつなぐ。

画面表示を見る `t_gfx_fb` はコンソール(tty)だけで表示され、X や Wayland では出ない。`t_input_live` は走らせている間にキーを押すと増える。この二つは、第26章・第29章で述べたとおり、実機で確かめていない範囲に入っている。

## 限界

- 表の「走らせていない」の行は、スクリプトの冒頭の説明文を読んだだけです。`test_laws.py` は、時間がかかるためこの付録では回していません。
- 乱数テストの「今回」の値は種 1 の 100 件です。第24章の 900 件×3 型とは別の実行です。
- Pi での手順は `pi_check/README.md` の説明です。この付録では Pi を走らせていません。README には「実機では未実行」という古い一文が残っていますが、実機の結果は第26章で扱ったとおりです。
- `spec_track.py` の結果は、今の仕様リポジトリを読んだときのものです。仕様が更新されれば変わります。

**仕様由来と実装の選択。** テストの仕組みは実装だけの選択です。`spec_track.py` の見本は仕様文書から直接取り込んだもので、仕様由来です。それ以外の期待値(整数の厳密計算や疑似カーネルの予想)は実装で作った期待値です。
