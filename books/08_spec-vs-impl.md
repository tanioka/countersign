## はじめに

この巻は、「今見ている結果は、仕様どおりなのか、この実装だけの動きなのか」を、動かしながら見分けるレシピ集です。第1巻から第7巻で付けてきた印を集め、仕様書と照らして、もう一度動かして確かめました。最初に見た動きは「これが正しい」として残りやすいので、学び始めに区別しておく価値があります。

各レシピは「やりたいこと、操作、実行結果、仕様書はどうか、ひとこと」の順です。実行は既定のモードで行い、確かめた版は『alpha1 実装 2026-11-06 00:50 JST』です。`--strict` は、第3章で確かめる道具としてだけ使います。【仕様】value_spec.md の V9 は「定義でない行の値はファイルでは捨てる」と書いています。【実装】この実装は、2026-11-04 22:40 の版から --strict でそれに合わせたので、--strict で走らせると最後の行の値は画面に出ません(print などで出した文字は出ます)。この本で「--strict でも同じ」と書いた所は、値を取り出して既定と比べた結果です。

**綴りについて** この巻は、実装の既定の動作が出した結果をそのまま書くので、「値が無い」を `__` と書いています。2026-11-10 から 13 の仕様の改定で、仕様の綴りは `!_`(void)になり、`_` は恒等射と穴になりました。以下の `__` は、仕様では `!_` に当たります。手で書いた `!_` は、`--strict` が断ります(R138)。

コマンドは、bash で打つ形で書いています。確かめたのは Linux の上だけで、Windows や macOS では試していません。

型に当てはまらないレシピがあります。レシピ6 と レシピ8 は「ひとこと」の代わりに「気をつける点」を置いています。レシピ10 は仕様書を検索した記録で、「実行結果」を「結果」とし、「仕様書はどうか」と「ひとこと」は置いていません(結果の表がその答えです)。レシピ11 は印を直した記録なので、「操作」を置かず「結果」と書いています。

結果の出どころは、どの巻とも同じ印で区別します。

- **【仕様】** 配布された仕様書に書かれた動作です。この巻では、どのファイルのどこにあるかを、ファイル名で示します。
- **【実装】** `sign_interp.py` がそう動くだけで、仕様書に見つからない動作です。別の処理系では同じになるとは限りません。
- **【拡張】** 仕様に無い、この実装に添えた道具です。

この巻のもう一つの目的は、過去の巻の印を見直すことです。調べ直した結果、割り算の丸め方は「実装」ではなく「仕様」でした。第1巻と第6巻にあった、この点の印の付け間違いは、この巻と同時に直しています。

**確かめた範囲** 1台のパソコンの中で、`sign_interp.py` を動かして結果を取りました。仕様書は、配布された `type_system.md`、`list_model.md`、`system_semantics.md`、`README.md` を読み、該当の箇所だけを照らしました。仕様書を全部読んで照らしたわけではありません。第4章のレシピ12 だけは、もう一つの処理系(Sign の作者の GitHub にある Playground)でも走らせて、結果を比べています。照らせなかったものは、「確かめていないこと」としてそのレシピに書いています。

Sign の資料は [johnny-shaman/Sign](https://github.com/johnny-shaman/Sign) にあり、仕様書に無い話は [Discussions](https://github.com/johnny-shaman/Sign/discussions) に出てきます。

## 第1章 数と計算

最も誤解が残りやすいのは、割り算のような「あたりまえ」の計算です。この章では、仕様書と照らして印を確かめます。

### レシピ1 割り算と剰余の丸め方

**やりたいこと** 負の数を割ったとき、答えがどう丸められるかを知りたい。

**操作** 次のプログラムを `d1.sn` として保存し、実行します。負の数は `0 - 5` のように引き算で作ります。

```
`std.sn`@~
show : label v ? seq3 (print label) (println_int v) 0
seq8 (show `5/2   ` (5 / 2)) (show `-5/2  ` ((0 - 5) / 2)) (show `-5%2  ` ((0 - 5) % 2)) (show `7/2   ` (7 / 2)) (show `4/3   ` (4 / 3)) (show `-7/2  ` ((0 - 7) / 2)) (show `-7%3  ` ((0 - 7) % 3)) 0
```

```
python3 sign_interp.py d1.sn
```

**実行結果**

| 式 | 結果 |
|---|---|
| `5 / 2` | 2 |
| `(0 - 5) / 2` | -2 |
| `(0 - 5) % 2` | -1 |
| `7 / 2` | 3 |
| `4 / 3` | 1 |
| `(0 - 7) / 2` | -3 |
| `(0 - 7) % 3` | -1 |

式 `(a / b) * b + a % b` を計算すると、`a = -7, b = 2` で -7、`a = 24, b = 5` で 24、`a = -5, b = 3` で -5 と、どれも `a` に戻りました。

**仕様書はどうか** 【仕様】`type_system.md` の「除算(`/`)は割り目の丈である。丸めない」の節に、同じ結果が書かれています。`-5 / 2` は `-2`(「0 方向へ落とす」)で、除法の等式 `a = (a / b) * b + a % b` が成り立つともあります。この節は、四捨五入ではないことも、理由とともに書いています。

**ひとこと** 第1巻の `24 / 5` と、第6巻の `(0 - 7) / 2` には【実装】の印を付けていましたが、どちらも【仕様】です。印の付け間違いだったので、直します。

**確かめていないこと** 小数(`Float`)が混ざる割り算と、大きすぎる数での割り算は、動かしていません。仕様書は、これらを別の規則として書いています。

### レシピ2 0 で割る

**やりたいこと** 0 で割ったときに、何が起こるかを知りたい。

**操作** 1 行だけのプログラムを、式を変えて実行します。初めの 3 つでは、結果の省略形 `|` を使います(左がここで迷ったときは右を返す式)。

```
7 / 0
7 % 0
(7 / 0) | 99
```

**実行結果** 【実装】`7 / 0` と `7 % 0` は、どちらも `__`(単位、「答えが無い」を表す値)と出ました。`(7 / 0) | 99` は 99 でした。`--strict` でも同じ結果です。

**仕様書はどうか** 【仕様】`type_system.md` は「0 で割ると、整数の商も剰余も `__` である」とし、`|` で受けられるとも書いています。実行結果と一致します。ただし同じファイルの「alpha の現状(規則ではない)」の注釈は、alpha はまだ旧い規則で答える(0 で割ると商は 0、剰余は被除数)と述べています。このパソコンで動かした `sign_interp.py` は、新しい規則の答えを返しました。注釈と実際の動きが食い違うことは確かめましたが、どちらが最新なのかは、ここでは判断しません。

**ひとこと** どちらの規則を読んでも、「仕様書の記述と、いま動く処理系が違うことがある」例として覚えておくと役立ちます。小さなプログラムを書いて確かめるのがいちばん確実です。

**確かめていないこと** 符号なし整数や番地を 0 で割る場合は動かしていません。

### レシピ3 整数の並びは 4 番地刻み

**やりたいこと** 整数を並べるときの番地の刻みを確かめたい。

**操作**

```
`std.sn`@~
A : 0x500000
seq3 (arr_set A 0 11) (arr_set A 1 22) (@(A + 4))
```

**実行結果** 【実装】結果は 22 でした。1 番目の要素が、先頭から 4 番地先にあります。

**仕様書はどうか** 【実装】この 4 番地刻みは、`std.sn` の約束です。`type_system.md` の List の大きさの表には、要素 1 つを 8 byte とした記述(`[1 2 3 4 5]` が 40 byte)があります。これはコンパイラが作る表現の話で、`std.sn` の配列と同じものかどうかは、確かめていません。

**ひとこと** メモリを直接見るプログラムを書くときは、「`std.sn` の約束」をまったく同じとは考えずに、自分で確かめるのが安全です。

**確かめていないこと** `0x500000` のあたり以外の番地で同じ刻みになるかは、試していません。

## 第2章 実行と出力

この章では、「実行すると、最後に何かが出る」「オプションを付け忘れると何も起きない」という、初めに目にする動きを、仕様と実装に分けます。

### レシピ4 最後の式の値を画面に出す

**やりたいこと** どの実行結果の最後にも、計算した記憶のない数字が一つ出る理由を知りたい。

**操作** 1 行だけのプログラム `1 + 2` を実行します。

```
python3 sign_interp.py d4.sn
```

**実行結果** 【実装】`3` と出ました。プログラムの最後の式の値を、画面に出す動きです。

**仕様書はどうか** 【仕様】`string_and_comment.md` の「最終行の返値」に、「ファイルの最終行(最後の非コメント式)がそのファイルの返値になる」とあります(すべてのファイルは関数です)。ここまでが仕様です。その返値を実行時に画面へ出すことは、このファイルの範囲では見つからず、【実装】と読んでいます。`README.md` にある参照実装の起動例は、最後の値を `console.log` で出していますが、これは起動例です。言語の規則として書かれているわけではありません。

**ひとこと** 結果の最後の数字は、計算の結果ではなく、表示の副産物と読んで構いません。別の処理系では、出ないこともあります。

**確かめていないこと** `execution_model.md` も「最後の式」「評価結果」で検索しましたが、画面へ出す規則は見つかりませんでした。全文は読んでいません。

### レシピ5 `#` は書いた番地を返す

**やりたいこと** メモリへの書き込みの式が、何を返すかを知りたい。

**操作** 2 つの 1 行プログラムを実行します。

```
0x500000 # 7
```

```
`std.sn`@~
seq2 (0x500000 # 7) (0)
```

**実行結果** 1 つ目は `5242880` と出ました(16 進で `0x500000`、書いた番地)。2 つ目は `0` でした。

**仕様書はどうか** 【仕様】`operator_table.md` の段 4 に、中置 `#`を「アドレスにデータを入れ、成功したらアドレスを返す」とあります。実行結果と一致します。その番地を画面に出すのはレシピ4と同じ、【実装】の表示です。

**ひとこと** 1 つ目の大きな数字は、書き込みの結果ではなく、「どこに書いたか」です。結果の最後に大きな数字が出たときは、最後の式が `#` で終わっていないかを見ます。

### レシピ6 オプションを付けないと何も起きない

**やりたいこと** 装置への書き込みが、オプションの有無でどう変わるかを確かめたい。

**操作** GPIO(入出力ピン)の受け口の番地 `0x9500000` へ、値 1 を書く 1 行を、オプションの有無で実行します。

```
0x9500000 # 1
```

```
python3 sign_interp.py e1.sn
python3 sign_interp.py --gpio=fake e1.sn
```

**実行結果** 【拡張】オプション無しでは、`156237824`(書いた番地の 10 進での表示)だけが出て、エラーは出ませんでした。`--gpio=fake` を付けると、`[gpio] 0 = 1` という行が追加で出ました。

**仕様書はどうか** 装置の受け口と `--gpio` などのオプションは、仕様書では見つからず、この実装に添えた道具です。第2巻と第4巻で見た「付けないと何も起きない(`__` や `0` だけが出る)」も、この道具の動きです。仕様書を拠り所にすると、ここで迷います。

**気をつける点** このパソコンで、装置をつなぐオプション(`--sys`、`--gpio`、`--i2c` など)を付け忘れると、なぜ動かないのかを示すエラーは出ません。「結果が空」のときは、まずオプションを疑います。

**確かめていないこと** `--sys` や `--i2c` など他のオプションを今回は動かしていません(第2巻と第4巻で確かめた結果をここで再現していません)。

## 第3章 仕様書で確かめきれないとき

ここでは、動かした結果は確かでも、「仕様」と言い切れない例を、そのまま記します。印を無理に付けず、「確かめていない」を残すのがこの章の仕事です。

### レシピ7 構造体を番号で引く

**やりたいこと** 名前の付いた要素を持つもの(構造体)を、番号で引いたときの結果を確かめたい。

**操作**

```
ann : [
	name : `Ann`
	age : 31
]
ann ' 0
```

3 行目の式を `ann ' age`、`[ann] ' 0` に変えたものも実行しました。さらに、`[7] ' 0`、`7 ' 0`、`[7 8] ' 0`、`[7 8] ' 1` を実行しました。

**実行結果** 【実装】

| 式 | 結果 |
|---|---|
| `ann ' 0` | `Ann` |
| `[ann] ' 0` | `Ann` |
| `ann ' age` | 31 |
| `[7] ' 0` | 7 |
| `7 ' 0` | 7 |
| `[7 8] ' 0` | 7 |
| `[7 8] ' 1` | 8 |

**仕様書はどうか** `list_model.md` に「1要素リストとスカラーは同型」とあり、`ann` と `[ann]` が同じ結果になること、`7` と `[7]` が同じ結果になることは、これと矛盾しません。名前の付いた要素を番号で引くときの結果は、この実装の版で変わりました。2026-11-08 より前の版は `__` を返し、この表もそう書いていましたが、この日の版からは定義の順の位置で引き、`ann ' 0` は `Ann`、`ann ' 1` は 31 を返します(既定の動作も `--strict` も同じ)。この位置で引く読みが仕様書のどの箇所に当たるかをこの章では確かめ直していませんので、今も「この処理系の観察結果」として【実装】の印を付けています。

**ひとこと** 構造体は名前(`age`)で引くのが確かです。番号で引く書き方は、実装の版で結果が変わったもの(以前は `__`、いまは定義の順の位置)なので、名前で引くほうが安全です。

**確かめていないこと** 構造体を番号で引くことについて仕様書が何としているか。読んだのは `list_model.md` の一部だけです。

### レシピ8 Sign の文字列をそのまま渡すと終わらない

**やりたいこと** 文字列を探す関数に、Sign の文字列を直接渡したときの動きを確かめたい。

**操作**

```
`std.sn`@~
S : 0x500000
seq2 (str_put S `hello sign`) (str_find S `sign`)
```

5 秒で打ち切るようにして実行します。

```
timeout 5 python3 sign_interp.py d8.sn
```

**実行結果** 【実装】 5 秒待っても終わらず、打ち切りの終了コード 124 で止まりました。第6巻では 20 秒待っても終わらなかったと記しています。

**仕様書はどうか** `str_find` は `std.sn` の関数です。仕様書にはありません。【拡張】で、結果も【実装】の動きです。

**気をつける点** メモリの文字列を期待する関数には、`str_put` で写した番地を渡します。このプログラムでは、`str_find` に渡す第 2 引数も、同じように写した番地でないといけません。

**確かめていないこと** なぜ終わらないのか、原因は調べていません。

### レシピ9 `--strict` だけで断られる書き方

**やりたいこと** 既定のモードでは動くのに、`--strict` では断られる書き方があることを確かめたい。

**操作**

```
a : 1
a : 2
a
```

```
python3 sign_interp.py s1.sn
python3 sign_interp.py --strict s1.sn
python3 sign_interp.py --check s1.sn --strict
```

**実行結果** 【実装】既定のモードでは `2` と出て、動きました(後の定義が前を隠します)。`--strict` では「`エラー: ``s1.sn:2:1: name-duplicate: 名前 a がファイルのいちばん外で2回定義されています(2つ目を断ります。P2)`」となり、動きませんでした。`--check` に `--strict` を添えると、実行せずに「参考 1 件」と出ました。断りには数えられませんでした。この断りは、実際に `--strict` で走らせて初めて出ます。

**仕様書はどうか** 【拡張】実装の記録 `IMPLEMENTATION_NOTES.md` の冒頭に、この表の変更は「すべて `--strict` だけの変更で、既定の動作は変えていない」とあります。同じ名前を2回定義する書き方が、仕様書のどこに根拠があるのかは、確かめていません(このレシピの例は、以前の版では仮引数が関数を隠す形でした。仮引数の隠しは仕様の R133 で断りでなく知らせになったので、例を替えました。第9巻にその形があります)。

**ひとこと** `--strict` は、「今の書き方が仕様に沿うか」を先に調べる道具です。既定で動いたということだけで、仕様に沿うとは言えません。

**確かめていないこと** `--strict` で断られる他の書き方は、ここでは 1 例しか動かしていません。

## 第4章 残りの巻の印を照らす

第2巻から第7巻には、【拡張】と【実装】の印が合わせて七十以上あります(第2巻 25、第3巻 22、第4巻 26 だけで 73 個、第5巻以降は含みません)。この章では、一つずつではなく、種類ごとに仕様書を検索して照らしました。検索は、配布された仕様書のファイル(`.md`)とサンプル(`.sn`)の中を、語の一致で探すものです。見つからなかったということは、「語として見つからなかった」ということです。別の言い方で書かれている可能性は残ります。

### レシピ10 種類ごとに仕様書を探す

**やりたいこと** 【拡張】と印を付けた道具や関数が、本当に仕様書に無いかを確かめたい。

**操作** 仕様書のファイルの中を、次の語で検索します。

```
grep -l -- "sqlite" *.md *.sn
```

語を変えて繰り返しました。`grep` で探す部分は、シェル(bash)のコマンドです。Sign ではありません。

**結果** 次の表のとおりです。

| 種類 | 探した語 | 仕様書での結果 | 判定 |
|---|---|---|---|
| データベース・通信(第2巻) | sqlite、MQTT、HTTP、TCP、socket | どれも見つからず | 【拡張】のままで問題なし |
| 画面・文字・ゲーム機(第3巻) | font、sprite、display、screen、on_key、sleep | どれも見つからず(`tick` は `unit.md` の別の例にあるだけ) | 【拡張】のままで問題なし |

### レシピ12 この巻の例を、もう一つの処理系(Playground)でも走らせる

**やりたいこと** この巻の例が、`sign_interp.py` だけの動きなのか、もう一つの処理系でも同じなのかを見たい。

**操作** Sign の作者の GitHub リポジトリ(johnny-shaman/Sign)にある Playground(`alpha/javascript/playground/`、Node.js で動く JavaScript 版)を起動し、同じプログラムを `sign_interp.py` と Playground の両方で実行して、最後の値を比べました。第1巻から第8巻のコード例を取り出したもの49本が対象です(第7巻には単独のコードブロックが無く、第5巻は断片だけです)。

**実行結果** 同じ結果になったのは7本です。残りのうち、24本は Playground で止まりました(付属の `std.sn` の「関数を返す関数」を受け付けない、装置の窓口が無い、など)。動いたもので、結果が違った主なものは次のとおりです。

| プログラム | `sign_interp.py` | Playground |
|---|---|---|
| `7 / 0` | `__` | `0` |
| `7 % 0` | `__` | `7` |
| `(7 / 0) \| 99` | `99` | `0` |
| 構造体 `ann` を `ann ' 0` で引く | `__` | `Ann`(最初の項目) |
| `A : 0x500000` のあと `A # 7`、`@A` | `7` | `5242880`(番地そのもの) |
| 第1巻の配列の合計(`0x500000` を使う) | `150` | `26214440` |
| `7 / 2`、`-7 / 2`、`[7 8] ' 1` | `3`、`-3`、`8` | `3`、`-3`、`8`(同じ) |

リストの表示も違います。`sign_interp.py` は `[1, 2]`、Playground は `[1 2]` と出し、文字列を含むリストは Playground で文字が連結されて出ました。これは表示の違いで、値の違いとは区別しました。

**仕様書はどうか**

- 0 で割る動きは、`type_system.md` の中に「`__` になる」という新しい規則と、「alpha の現状」の注記(商 0、余りは割られる数)の両方があります。`sign_interp.py` は前者、Playground は後者と同じ結果でした。どちらが最新の決めなのかは、この巻では判断していません。
- 構造体を番号で引く動きは、今も仕様書で見つかっていません。処理系によって答えが分かれることが分かったので、この巻の例も、この書き方を使うものは、どちらの処理系の結果とも言い切れないものとして読んでください。
- 除算の丸め(0 の方へ)と、リストの要素を取り出す動きは、両方で同じでした。この2つは、試した2つの処理系では同じ答えになりました(仕様書の記述とも合うのは除算の丸めだけです)。

**ひとこと** この巻で【実装】と呼んできた動きは、「`sign_interp.py` の動き」で、他の処理系で同じになるとは限りません。このレシピは、そのことを実際の違いで示したものです。

**確かめていないこと**

- 取り出したコードは手で書き写したもので、本文と照らし合わせていません。
- Playground で `#` と `@` が「書き込めない」のか、こちらの使い方が合っていないのかは、Playground のソースで確かめていません。
- Playground では `parser.js` が同梱されていなかったため、この巻では peggy を GitHub から取ってきて生成しました(公式の手順とは違う生成です)。
- Playground で「動かない」ことを、バグとするか、未実装とするかは分けていません。
