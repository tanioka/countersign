この巻は、Sign のプログラムが「計算が多すぎる」「入れ子が深すぎる」ときにどう止まるかを、実際に走らせた結果で書きます。

## はじめに

止まらない輪を書いてしまったとき、深すぎる再帰を書いてしまったときに何が起きるか。そして、どう書けば上限に当たらないか。この三つを、例と結果で順に見ます。

この巻は、モードの違いが結果を左右します。この巻では、既定のモードを `python3 sign.py a.sn`、仕様の読みを確かめるモードを `python3 sign.py --strict a.sn` と書きます。上限の話は、主に `--strict` で起きます。既定のモードは「旧 alpha 互換」で、計算の量の上限と深さの上限を持ちません。ただし、同じ状態へ戻る輪は、既定のモードでも止めます。

書き分けは次のとおりです。

- 【仕様】：設計者の書いた value\_spec.md の V10（資源）・V11（知らせ）・V12（まだ）に書いてあること。
- 【実装】：この Python 実装（alpha1 実装 2026-11-06 00:50 JST）を走らせて出た結果。仕様が何も定めていないこともここに入ります。

時間は、ある1台の機械で測った値です。機械やスタックの大きさが違えば変わります。知らせやエラーの読み方を先に知りたい方は、[第9巻 知らせとエラーの読み方](09_messages-and-errors.md) を先にどうぞ。

## 第1章 既定のモードで、止まる輪と止まらない輪

既定のモードには計算の量の上限がないので、引数が増え続ける輪は、そのまま回り続けます。止めるには Ctrl-C です。

```
up : x ?
	up (x + 1)
up 1
```

これを `python3 sign.py a1.sn` で走らせ、外から 40 秒で打ち切りました。それまでには何も出ませんでした。次のように、同じ状態へ戻る輪は、既定のモードでも止まります。

```
spin : x ?
	spin x
spin 1
```

これを既定のモードで走らせると、0.05 秒でエラーになりました(終了コード 1)。

```
エラー: interpret-not-yet: 3 行目の末尾の輪が前に通った状態(同じ関数・同じ実引数)へ戻りました。止まらない輪(アイドル)です。この実装は輪を回さずに止めます(V10・V12。`_` は返しません)
```

【実装】これは既定モードの挙動です。仕様の V10 は、どちらも止めると書いています（第2章）。既定のモードは、同じ状態へ戻る輪は止めます。引数が増え続ける輪を止めないのは、計算の量の上限を持たず、旧 alpha と同じ振る舞いを残しているからです。

### 深い再帰

末尾でない再帰は、深さを使います。次は「1 を足していく」再帰です。値を見るために、標準ライブラリの `println_int` を `std.sn` から使います。

```
`std.sn`@~
deep : n ?
	n = 0 : 0
	1 + (deep (n - 1))
println_int (deep 50000)
```

既定のモードでは、次のように出ます。

```
50000
0
```

上の `0` は、`println_int` が返す `0` です。既定のモードは最後の行の値を表示するので、`50000` のあとにこの `0` が続きます。

この機械で測ったところ、既定のモードでは 90000 段までは答えが出て、100000 段では次のエラーで終わりました（終了コード 1）。

```
エラー: 再帰が深すぎます(スタックの大きさが足りません)
```

【実装】この境目はスタックの大きさに従うので、機械で変わります。仕様は既定のモードのこの挙動を定めていません。エラーで終わるだけで、落ちることはありません。

## 第2章 `--strict` では、行を名指しして止まります

`--strict` では、止まらない輪はエラーで止まり、終了コードは 1 になります。止まり方は輪の形で二つに分かれます。ともに `_` を返さず、重かった行を名指しします。

### 同じ状態へ戻る輪

第1章の `spin` は、末尾の輪が前に通った状態（同じ関数・同じ実引数）へ戻る形です。これは回す前に止まります。既定のモードでも同じ理由で止まり、同じメッセージが出て、行の名指しも付きます。

```
エラー: interpret-not-yet: 3 行目の末尾の輪が前に通った状態(同じ関数・同じ実引数)へ戻りました。止まらない輪(アイドル)です。この実装は輪を回さずに止めます(V10・V12。`_` は返しません)
```

時間は 0.19 秒でした。【仕様】呼び出しは関数と実引数で決まるので、同じ状態へ戻る輪は決して答えを出さない、と V10 は読みます。理由名は V12 の「まだ」の `interpret-not-yet` です。`_` を返すと答えが型に焼き付くため、返しません。

### 同じ状態へ戻らない輪

第1章の `up` は、引数が 1 ずつ増えて行くので、同じ状態へは戻りません。こちらは計算の量の上限で止まります。

```
エラー: interpret-work-limit: 3 行目の計算の量が上限(5,000,000 回)に届きました。止まらない輪かもしれません(末尾の輪が同じ状態へ戻らない形。V10)
```

この機械では 9.3 秒かかりました。【仕様】これは実装の都合なので `_` にせず、重かった行を名指しして止めるという書き方です。理由名は `interpret-work-limit` です。

「止まらない輪かもしれません」という言い方のとおり、このエラーは、いずれ終わる輪でも上限を超えれば止めます。確かめるために、終わるけれど量の多い輪を走らせました。

```
`std.sn`@~
lp : n acc ?
	n = 0 : acc
	lp (n - 1) (acc + n)
println_int (lp 5000100 0)
```

`--strict` では 5 行目で、上と同じ `interpret-work-limit` のエラーになりました（15 秒、上限は 5,000,000 回）。回数の数え方は、輪の繰り返しだけではありません。詳しい数え方は、この巻では確かめていません。

### 上限を変える

【実装】上限は環境変数 `SIGN_WORK_LIMIT` で変えられます。小さくすると、止まるまでが速くなります。

```
SIGN_WORK_LIMIT=100000 python3 sign.py --strict a.sn
```

これで `up` の例は、上限が `100,000 回` という同じ形のエラーで止まりました。【仕様】仕様の側の変え方は、試験の口 `interpret(source, { workLimit })` です。環境変数での変更は仕様にありません。

## 第3章 深さの上限を超えると、その呼び出しが `_` になります

`--strict` では、入れ子の深さが上限に届くと、エラーにはならず、その呼び出しが `_` となって知らせが出ます。この巻の実装では上限は 6237 段です。

第1章の `deep`（`1 + (deep (n - 1))`）を、段数を変えて両方のモードで走らせました。表の「既定」は、最後の行の `0`（第1章）を除いた答えです。

| 段数 n | 既定 | `--strict` |
| --- | --- | --- |
| 5000 | 5000 | 5000 |
| 6236 | 6236 | 6236 |
| 6237 | 6237 | 6237 + 知らせ |
| 6238 | 6238 | 6237 + 知らせ |
| 100000 | エラー（終了コード 1） | 6237 + 知らせ（終了コード 0） |

`--strict` で 6237 段以上にしたときの知らせは、次の形です。

```
知らせ: resource-depth: 入れ子の深さが上限(6237 段)に届いたので、この呼び出しは _ です(V10・V11)。再帰は末尾の呼び出しにすると深さを使いません [3 行目]
```

6238 段でも 100000 段でも答えが 6237 のまま増えないのは、上限を超えた所が `_` になった結果と読めます。知らせの最後にある `[3 行目]` は、入れなかった所の行です。

【仕様】V10 は、入れ子の深さを数え、上限で `_` と information を出すと書いています。V11 の表にも理由 `resource-depth` があります。【実装】上限の値は、再帰の上限を元に計算します（第4章）。

### 既定のモードとの違い

既定のモードでは、この上限はありません。この機械では、答えが出るか、スタックが足りずにエラーで終わるかのどちらかでした。同じプログラムで、モードを変えるだけで答えが変わることがあります（6238 段以上）。深い再帰を書くなら、第5章の末尾の書き方にすると、どちらのモードでも同じ答えになります。

### いま解けていないこと

1. 【仕様】R129 は「値が `_` の枝は消えて次へ進む」と書きます。深さの上限で出た `_` を、この「消える」対象に含めるかどうかは、仕様からは読めません。設計者への「未決の問い」に記録しています。この巻では、どちらの読みでも答えが変わらない例だけを使いました。
2. 【実装】次の形は、最初の枝（`n > 0 :`）の中で再帰します。仕様は「末尾は最後の枝と既定の行だけ」（R129）と書いているので、この再帰は末尾ではないと読めます。それなのに `--strict` で 10000 段を走らせても、知らせなしで答えが出ました。

```
`std.sn`@~
lp : n acc ?
	n > 0 : lp (n - 1) (acc + n)
	acc
println_int (lp 10000 0)
```

```
50005000
```

原因は調べていません。仕様と食い違う可能性があるので、記録だけしておきます。

## 第4章 上限の値は、仕様と実装で食い違います

上限の値は、仕様とこの実装で違います。止まり方（理由名と終わり方）は同じです。

| 項目 | 【仕様】value\_spec.md V10 | 【実装】走らせて確かめたこと |
| --- | --- | --- |
| 入れ子の深さの上限 | 1200 | 6237（再帰の上限 200000 から (200000 − 400) ÷ 32 で決める） |
| 1行の計算の量の上限 | 2000万回（仕様は「この機械で数秒」） | 500万回（止まるまで 9.3 秒） |
| 量の上限の変え方 | 試験の口 `interpret(source, { workLimit })` | 環境変数 `SIGN_WORK_LIMIT` |
| 深さの上限に届いたとき | `_` と information（`resource-depth`） | 同じ。終了コード 0 |
| 量の上限に届いたとき | `_` にせず、重かった行を名指しして止める（`interpret-work-limit`） | 同じ。エラーで終了コード 1 |
| 同じ状態へ戻る輪 | 回さず止める（`interpret-not-yet`） | 同じ。エラーで終了コード 1 |

今のところ、数字の食い違いは次のとおりに現れます。`deep`（第1章）を `--strict` で 2000 段にすると、この実装は知らせなしで 2000 を答えます。仕様の「1200」を固定の値と読むなら、この例は仕様では上限を超えます。

【仕様】仕様自身が、この二つの数字を「上限の値（実装の都合、R）」として書いています。深さの 1200 は、JS のスタックの測り直しで決めた値です。【実装】この実装は、Python のスタックに合わせて深さを決めています。この数字を仕様の数字に合わせるかは、設計者の決めることです。「固定の値と読むのか」を未決の問いに記録しています。仕様の文をこちらで直すことはしません。

【実装】深さの上限は、スタックの大きさに従い、小さいスタックでは下がります。この巻の 6237 は、再帰の上限が 200000 のときの値です。他の機械で同じ数字になるとは限りません。

## 第5章 上限に当たらない書き方

深さの上限は、再帰を末尾の呼び出しにすると避けられます。末尾の呼び出しは輪で回るので、深さを使いません。

第1章の `deep` と同じ、「1 から n までの和」を、答えを引数（`acc`）で持ち回る形にします。最後の行が、再帰の呼び出しそのものです。

```
`std.sn`@~
lp : n acc ?
	n = 0 : acc
	lp (n - 1) (acc + n)
println_int (lp 100000 0)
```

両方のモードで、100000 段でも次の答えが出ました。`--strict` でも、深さの知らせは出ません。

```
5000050000
```

第3章の `deep 100000` は、既定のモードでエラー、`--strict` で 6237 でした。同じ段数で、末尾の書き方にするだけで、どちらのモードも同じ答えになります。

【仕様】V10 は、末尾の呼び出しは輪で回すと書き、「返す所は綴りでなく意味で決める」としています。行の答えが最後の呼び出しの答えそのものなら末尾です。この巻では、この一つの形（枝の後に続く既定の行で呼ぶ）だけを走らせて確かめました。

### 輪の回数は残ります

末尾の書き方にしても、計算の量の上限は残ります。第2章の `lp 5000100 0` が、その例です。終わる輪でも、`--strict` では 500万回を超えると止められます。この上限を超える量の計算をするなら、既定のモードで走らせるか、【実装】`SIGN_WORK_LIMIT` を大きくして走らせます。

### この巻では確かめていない書き方

`&` と `|` で続ける形も、【仕様】では返す所に数えます（V10）。この巻では、この形での確かめはしていません。走らせてみた 1 例は期待どおりに動きませんでしたが、書き方の誤りか実装の差かを切り分けていません。確かめたのは、枝と既定の行の形だけです。

## 確かめた範囲と、確かめていないこと

この巻の例は、既定のモードと `--strict` の両方を実際に走らせて出した結果です。走らせたのは 2026-11-05 の実装で、深さの境目（6237 段）・100000 段・量の上限・末尾の書き方の答えは、alpha1 実装 2026-11-06 00:50 JST の版で走らせ直して、同じになることを確かめました。時間（0.19 秒・9.3 秒・15 秒）と、既定のモードの 90000 段まで答えが出て 100000 段でエラーになる境目も、同じ日に測り直しました。第1章の spin・up と、第2章の lp 5000100 は、既定のモードに止まらない輪の検出を入れた版(2026-11-06)で、既定のモードを走らせ直しました(spin は 0.05 秒で止まり、up は 40 秒で打ち切り、lp は 12.5 秒で 12500502505050 を答えました)。時間は、ある1台の機械で、あるときに測った値です。機械の負荷で変わります。

**確かめたこと**

- 止まらない輪（2種類）のうち、同じ状態へ戻る輪は既定のモードでも止まり、引数が増え続ける輪は既定のモードでは止まらず、`--strict` ではどちらも行を名指しして止まること（第1・2章）。
- 深さの上限の境目（6236 / 6237 / 6238 / 100000 段）と、既定のモードでは 90000 段まで答えが出て 100000 段でエラーになること（第3章）。
- 5,000,100 回の輪が量の上限で止められること、`SIGN_WORK_LIMIT` で上限を変えられること（第2章）。
- 末尾の書き方で 100000 段がどちらのモードでも同じ答えになること（第5章）。

**確かめていないこと**

- 仕様の「量は行ごとに数え直す」（問16）。ファイルの複数の行に重い計算を置いての確かめはしていません。
- 互いに呼ぶ関数や、値の定義の輪が止められる形（V12）。
- 複数の機械やスタックの大きさでの深さの上限。この巻の数字は 1 台分です。
- 対話モード（コンソール）での止まり方。
- `&` と `|` で続ける末尾の形。

**この巻で見つけた、仕様と食い違うかもしれないこと**

第3章の最後の例（最初の枝の中で再帰して、`--strict` で 10000 段を走らせても知らせが出ない形）。これは設計者への「未決の問い」に記録しています。
